# 存档（Save）

> **Status**: In Design
> **Author**: user + agents
> **Last Updated**: 2026-11-04
> **Last Verified**: 2026-11-04
> **Implements Pillar**: 数字看得见地涨

## Summary

存档是《回本》唯一的跨会话持久层：它把钱包、升级等级、解锁与纪录写成一份带版本号的生涯档，启动时校验、必要时逐级迁移，写入时保证原子性并保留一份备份。它不解释任何数字的含义——钱包怎么加减、纪录怎么比较由局外升级与纪录系统拥有；它只保证这些值在一次崩溃、一次改版或一次误删之后仍然对得上。

> **Quick reference** — Layer: `Core` · Priority: `MVP` · Key deps: `数据配置`

## Overview

存档是《回本》里唯一跨会话存在的东西。一局之内的一切（菜单、饱腹、腻度、净利）都在结算后丢弃；留下来的是**局外状态**：玩家有多少钱、哪些升级升到几级、哪些档口与菜已解锁、最好的成绩与已达成的里程碑。这些值由各自的系统计算，存档只负责把它们完整、可恢复、可迁移地放进一个文件。

它对玩家是隐形的：没有"保存游戏"按钮，也没有存档槽选择。玩家在结算页看到的钱包变化、在升级页按下购买的那一刻，存档就已经把结果落盘了；下次打开游戏，数字还在。它存在的意义不是让玩家管理文件，而是让"数字看得见地涨"这条支柱跨过进程边界——涨上去的数字必须真的属于玩家。

对下游系统，存档是一份**带版本的信封**：每个系统拥有自己的命名空间，只把自己算完的新值交进来；存档校验结构、原子写入、维护版本与迁移，从不替任何系统做玩法判断。这条边界让钱包规则、解锁条件与纪录排名可以各自演化，而不必改动持久化格式的语义。

## Detailed Design

### Core Rules

1. **职责边界** — 存档拥有：生涯档的 schema 与版本号、载入结果与报告、原子写入、备份与隔离、版本迁移、单写者约束。它不拥有：钱包的加减与钳制（局外升级）、解锁条件与免费档口（解锁与档口）、纪录排名与里程碑判定（纪录与里程碑）、每日挑战规则（在线挑战）、设置项（界面流程/音效反馈）。存档保存这些系统算完之后的**值**，不替它们计算。
2. **只存 id 与值，不存数据快照** — 存档不保存任何从数据配置派生的运行期数值：价格、饱腹、口味标签、腻度分组、`max_level`、`effect_value`、`entry_fee`、`dish_pool` 都不写进生涯档。载入后用 id 向数据配置重新取记录。本规则直接承接数据配置规则 6 与它的下游契约「读取时不信任存档里的数值快照」。
3. **例外：纪录里的历史事实** — 纪录可以保存当时的 `entry_fee`、`total_value`、升级等级快照等历史事实，因为它们描述「那一局发生了什么」，只用于展示与比较，不参与任何运行期计算（结算 GDD 规则 13 与 Open Question 3）。这些字段的语义归纪录与里程碑，存档只提供存放位置。
4. **MVP 一份生涯档** — 一个 OS 用户一份生涯，`MAX_SLOTS = 1`。没有手动存档/读档界面，没有多档选择。schema 保留 `slot_id` 字段，为后续多档预留，届时只放宽 `MAX_SLOTS`，不改变信封结构。
5. **MVP 不做中途存档** — 一局从 `Menu → Run` 到结算是一个整体；放弃、进入失败或局中退出都使本局作废（场景与流程管理规则 8 / 10）。存档只持久化局外状态。腻度与口味为「若启用中途存档」预留的计数表与规范组序契约、菜单波次为「若启用中途存档」预留的 `seed` / `wave_index` / 本波剩余契约，在 MVP 均不生效；启用时必须新增 schema 版本，见 Open Question 1。
6. **自动保存，无保存按钮** — 存档在四个时点写入，且只在内存为 dirty 时写：① 首次建立生涯；② 一次结算引起的局外变化；③ 一次购买或解锁成交；④ 退出游戏或返回菜单前的 flush。玩家不选择保存时机，也不能手动跳过保存。
7. **只写当前版本** — 存档只以当前 `SAVE_SCHEMA_VERSION` 写出；不写旧版本，不提供「导出为旧版」。
8. **原子提交** — 一次写入要么完整生效，要么完全不生效。写入顺序固定为：校验 → 写临时文件 → flush → 主档改名备份 → 临时文件改名主档。任何一步失败，主档保持原样，临时文件删除，事务报告失败。
9. **备份保留一份** — `SAVE_BACKUP_COUNT = 1`，备份保存的是**上一次成功写入**的完整主档。备份不是同步副本，它总是落后一个成功事务；这也是恢复时可能损失最近一次事务的原因，恢复报告必须如实说明。
10. **载入结果六态** — `Fresh`（无档）、`Loaded`（当前版本、结构合法）、`Migrated`（从旧版本迁移成功）、`Recovered`（主档不可用、备份可用）、`ReadOnly`（另一实例持有存活写锁，但主档可读且版本 ≤ 当前，可浏览不可写；旧版本用内存中的只读迁移渲染，不写盘）、`Blocked`（无可用副本、版本高于游戏、迁移失败、或持锁且文件不可读）。每种结果附一份 `LoadReport`（来源版本、原因码、警告列表、是否可写）。
11. **载入永不阻断启动** — 存档不驱动顶层状态切换。任何载入结果（包括 `Blocked`）都让 `Boot → Menu` 照常发生（场景与流程管理规则 4）；`Blocked` 时写入被禁用，由界面流程在进入 `Menu` 后显示说明。存档不静默覆盖、不自动删除任何文件。
12. **版本高于游戏 = 拒绝** — 存档版本 `>` 当前游戏版本时，不加载、不迁移、不回退到备份、不覆盖。避免旧程序读新档丢掉新字段。只有在**无存活写锁**且玩家明确选择「新建生涯」时，旧档才被改名隔离（规则 21）。
13. **迁移是单向链** — 旧版本逐级迁移：`v → v+1 → … → n`。每一步是纯函数，只依赖存档自身与该步定义，不读时钟、不读运行期状态、不联网。任何一步失败，载入结果为 `Blocked`，原文件保持不变。
14. **未知条目原样保留** — 载入时遇到当前数据配置不认识的 upgrade / dish / station id，或在 `extensions` 中遇到不认识的键：不删除、不重写，原样保留并在 `LoadReport` 中报告。已知条目正常生效；未知条目在运行期不生效（等级不提供效果、解锁不生效），但下次写盘时原样写回——数据修好后自然恢复。
15. **数值越界钳制并报告** — 升级等级高于 `UpgradeData.max_level` 时钳制到 `max_level`；低于 0 时按 0 处理。每次钳制写入 `LoadReport.warnings`，不静默。字段类型不是整数（字符串、浮点、布尔）或文件截断属于结构错误，走损坏路径，不做逐字段抢救——钳制只用于数值越界，不用于类型错误。
16. **钱包是有符号 int64，存档不改策略** — 存档原样往返 `wallet`，不钳制为 0、不取绝对值、不设上限。净利如何进入钱包是局外升级的规则（结算 GDD Open Question 1）。存档只保证整数精度无损：`wallet = 9007199254740993` 往返后仍是同一个数。
17. **购买先落盘再确认** — 局外升级 / 解锁的成交顺序是：内存应用 → 写盘 → 成功后界面才显示成交。写盘失败则回滚内存变化并返回失败；玩家看到「未保存，购买未生效」，钱包与等级不动。不允许出现「界面说买了、重启后没了」。
18. **结算产生的局外变化失败可重试** — 结算产生的钱包入账（`progression`）、纪录（`records`）与解锁统一先记在内存并标记 dirty；写盘失败时保留内存值、提示「未保存」，在下一个写入时点（下一次结算 / 购买 / 退出）重试。一局已经结束，回滚这些变化等于丢弃这一局的事实，因此它们与购买使用不同的失败策略（购买按规则 17 回滚）。
19. **放弃与进入失败不写档** — 放弃一局（`Paused → Menu, abandoned`）、`RunConfig` 解析失败、局中退出都不产生任何存档写入；存档内容与进入本局前逐字段相同（场景与流程管理 AC 10）。
20. **设置不属于生涯档** — 音量、画面、无障碍等设置存放在独立的机器级配置，不随生涯档删除、不随生涯档备份、不进入云同步。删除生涯不重置设置；重置设置不动生涯。
21. **单写者** — 同一份生涯档同时只允许一个实例写入。启动时建立写锁（含实例标识与时间戳）；检测到存活的另一实例且主档可读、版本 ≤ 当前时，本实例载入结果记为 `ReadOnly`（可只读浏览，写入禁用）；文件不可读或版本 > 当前时记为 `Blocked`。**任何 `L = live` 的 `Blocked` 出口只有「退出」与「重试」**，不提供「新建生涯」——对方可能正处在「主档改名备份 → 临时文件改名主档」的原子窗口内，隔离会破坏对方文件。绝不覆盖对方的文件。进程崩溃遗留的锁以进程存活为主、时间戳为辅回收；无法判定时按「存活」处理——宁可只读，不可覆盖。
22. **时间戳只做元数据** — 存档记录 `created_at` / `last_saved_at`（UTC），仅用于界面显示与载入报告；任何逻辑（排序、冲突、过期、迁移分支）都不得依赖系统时钟，因为时钟可能回拨或被玩家修改。
23. **删除生涯是显式且可恢复的** — 删除生涯必须由玩家在界面二次确认；存档把现有文件改名隔离而非删除，然后建立新档。隔离文件不自动清理，也不计入备份轮换。
24. **确定性往返** — 同一份内存状态连续写两次（不改变任何值，排除 `last_saved_at`）产生逐字节相同的文件：map 按键排序、整数按十进制、无随机 id、无平台相关换行。这让 diff 可读，让「往返不变」成为可断言的测试。
25. **不做防篡改** — 单机信任模型。不加密、不设校验和来阻止编辑；手工编辑过的档按普通结构校验处理，类型或结构不合法就走损坏路径。将来若排行榜需要可信数据，由在线挑战在服务端解决，不由本地存档假装解决（Open Question 5）。

### States and Transitions

存档有两个独立的状态维度：**载入结果**（一次性的，决定了本实例是否可写）与**写入生命周期**（运行期反复变化）。

**载入结果**（`LoadReport.outcome`）：

| 结果 | 判定 | `writable` | 后续行为 |
|---|---|---|---|
| `Fresh` | 主档与备份都不存在 | 是 | 用默认值建立生涯，立即写入一次基线 |
| `Loaded` | 主档可读、版本 = 当前、结构合法 | 是 | 直接使用 |
| `Migrated` | 主档可读、版本 < 当前、迁移链成功 | 是 | 立即写回当前版本；若写失败则保持 dirty 并重试 |
| `Recovered` | 主档不可用、备份可读且版本 ≤ 当前、迁移成功 | 是 | 使用备份内容，报告可能丢失的事务；下次写入重建主档 |
| `ReadOnly` | 另一实例持锁、主档可读、版本 ≤ 当前 | 否 | 可浏览；写入禁用；旧版本用内存只读迁移渲染（不写盘）；不提供「新建生涯」 |
| `Blocked` | 无可用副本 / 主档版本 > 当前 / 迁移失败 / 持锁且文件不可读 | 否 | 按锁与原因给出口，锁优先：`L = live` → 任何原因都只给「退出」「重试」，不提供「新建生涯」；`L ≠ live` 时：更新版本 / 无法读取 → 退出 / 新建生涯；迁移失败 → 退出 / 重试 |

**写入生命周期**：

| 状态 | 触发 | 下一个状态 | 说明 |
|---|---|---|---|
| `Clean` | 载入完成 / 写盘成功 | `Dirty` | 内存与磁盘一致 |
| `Dirty` | 结算、购买、解锁或迁移产生新值 | `Saving` | 内存领先于磁盘 |
| `Saving` | 调度器执行写入 | `Clean` | 写盘成功；备份轮换为主档，临时文件成为新主档 |
| `Saving` | 写盘失败，事务来自购买 | `Clean` | 回滚该次内存变化，返回 `CommitFailed`；磁盘未变 |
| `Saving` | 写盘失败，事务来自结算入账 / 纪录 / 迁移 | `Dirty` | 保留内存变化，返回 `SaveDeferred`，下一个时点重试 |
| `Clean` / `Dirty` | 载入结果为 `Blocked` / `ReadOnly` | `Blocked` / `ReadOnly` | 禁止任何写入；不产生临时文件 |
| `Blocked`（更新版本 / 无法读取，且无存活写锁） | 玩家确认新建生涯 | `Fresh` → `Clean` | 旧文件改名隔离，建立默认生涯并写入 |
| `Blocked`（迁移失败 / 持锁不可读） | 玩家确认重试 | `Unloaded` → `Loading` | 调用 `retry_load()` 重新读取，替换缓存的 `LoadReport`；不隔离文件 |
| 任意（`L ≠ live`） | 玩家确认删除生涯 | `Fresh` → `Clean` | 同上；设置不受影响 |

同一帧内出现多个事务时按到达顺序串行写入；一个事务的写入未结束前不开始下一个，不允许交错。一次结算引起的钱包、纪录与解锁变化必须合并为**同一个事务**，不得拆成多次写入。

### Interactions with Other Systems

| 系统 | 方向 | 数据/接口 | 硬/软 |
|---|---|---|---|
| 数据配置 | 上游 | `get_upgrade(id)` → `max_level`；`get_station(id)` / `get_dish(id)` 校验 id 是否存在；载入前提 `Ready` | 硬 |
| 局外升级 | 下游 | 拥有 `progression` 命名空间：`wallet`、`upgrade_levels`；通过 `commit({progression: …})` 提交新值 | 硬 |
| 解锁与档口 | 下游 | 拥有 `unlocks` 命名空间：`stations`、`dishes` 两组 id | 硬 |
| 纪录与里程碑 | 下游 | 拥有 `records` 命名空间：按档口纪录、生涯合计、已达成里程碑 id；字段语义与排名规则由它定义 | 硬 |
| 在线挑战 | 下游（未来） | 拥有 `challenges` 命名空间；MVP 不存在，随 schema 迁移加入 | 软 |
| 界面流程 | 下游 | 读取 `LoadReport` / `SaveStatus` 显示「已保存」「从备份恢复」「无法写入」；发起删除生涯请求 | 硬（UI） |
| 场景与流程管理 | 无直接调用 | 只共享启动时序：数据 `Ready` 之后、进入 `Menu` 之前完成载入；存档不发起任何顶层切换 | 软（编排） |

**接口所有权**：存档拥有信封（`schema_version`、`career_id`、`created_at`、`last_saved_at`、`slot_id`、`extensions`）、结构校验、原子性与迁移。每个下游系统拥有自己命名空间的字段与含义；存档不解释、不推导、不替它们做玩法判断。

**对外接口（设计级）**：

| 接口 | 输入 | 输出 | 说明 |
|---|---|---|---|
| `load()` | — | `LoadReport` | 仅在数据配置 `Ready` 后调用一次；重复调用返回同一结果，不重复读写；重试走 `retry_load()` |
| `retry_load()` | — | `LoadReport` | 仅在 `Blocked`（迁移失败 / 持锁不可读）时由界面调用；重新执行完整载入并替换缓存的 `LoadReport`，不隔离文件 |
| `get_namespace(owner)` | 命名空间名 | 只读字典 | 下游只读；修改必须经 `commit` |
| `commit(transaction)` | `{命名空间: 新值}` | `CommitResult` | 整笔事务原子生效；成功后磁盘已更新；购买失败回滚内存，结算入账 / 纪录 / 迁移失败标记 dirty 并重试 |
| `mark_dirty(namespace)` | 命名空间名 | — | 供纪录类更新使用：先改内存，再在下一时点写 |
| `flush()` | — | `FlushResult` | 退出或返回菜单前调用；dirty 时写盘 |
| `save_status_changed` | — | 信号 | 携带 `SaveStatus`，供界面显示指示与错误 |
| `delete_career()` | 确认令牌 | `Result` | 隔离旧文件并建立新生涯；无确认令牌则拒绝 |

**信封与命名空间结构**（设计级 schema，具体序列化格式见 Open Question 2）：

| 字段 | 类型 | 所有者 | 默认值 | 载入校验 |
|---|---|---|---|---|
| `schema_version` | int | 存档 | 当前版本 | 必须为正整数；否则损坏 |
| `career_id` | String | 存档 | 创建时生成 | 非空、稳定；缺失走迁移 |
| `slot_id` | int | 存档 | 0 | 0 ≤ `slot_id` < `MAX_SLOTS` |
| `created_at` / `last_saved_at` | String (UTC ISO-8601) | 存档 | 创建时刻 | 仅展示，不参与逻辑 |
| `progression.wallet` | int64 | 局外升级 | 0 | 整数；有符号；不钳制 |
| `progression.upgrade_levels` | map<String, int> | 局外升级 | 空表 | 等级 ≥ 0；超过 `max_level` 钳制并报告 |
| `unlocks.stations` / `unlocks.dishes` | String[] | 解锁与档口 | 空数组 | 元素唯一；未知 id 保留 |
| `records.*` | #14 定义 | 纪录与里程碑 | 0 / 空 | 类型合法即可；语义由 #14 校验 |
| `extensions` | map<String, Variant> | 存档（内容归写入方） | 空表 | 原样往返；计入体积上界 |

**命名空间归属规则**：一个事务可以同时更新多个命名空间（例如结算后钱包、纪录、解锁一起变），但每个命名空间的内容只能由它的所有者计算。存档不做跨命名空间的语义检查，只拒绝结构性非法（类型错误、负数等级、重复 id）。

## Formulas

本系统定义四个数值规则：载入判定、迁移链、存档体积上界与可用槽位。它们都是可判定的，因为它们决定「能不能启动」「写不写得下」「还能不能建新档」，不能只靠散文描述。

### 载入结果 `load_outcome`

The `load_outcome` formula is defined as:

`load_outcome(P, B, V, L) =`

- `Blocked`，若 `readable(P) ∧ version(P) > V`
- 否则 `ReadOnly`，若 `L = live ∧ readable(P)`
- 否则 `Blocked`，若 `L = live`
- 否则 `Fresh`，若 `P = ∅ ∧ B = ∅`
- 否则 `Loaded`，若 `readable(P) ∧ valid(P) ∧ version(P) = V`
- 否则 `Migrated`，若 `readable(P) ∧ valid(P) ∧ version(P) < V ∧ migrate(P, version(P), V) ≠ error`
- 否则 `Blocked`，若 `readable(P) ∧ valid(P) ∧ version(P) < V ∧ migrate(P, version(P), V) = error`
- 否则 `Recovered`，若 `readable(B) ∧ valid(B) ∧ version(B) ≤ V ∧ migrate(B, version(B), V) ≠ error`
- 否则 `Blocked`

**Variables:**

| Variable | Type | Range | Source | Description |
|---|---|---|---|---|
| `P` | SaveFile \| ∅ | 一个文件或不存在 | 文件系统 | 主档 |
| `B` | SaveFile \| ∅ | 一个文件或不存在 | 文件系统 | 最近一次成功写入前的备份 |
| `V` | int | 1–INT32_MAX | constant | 当前游戏的 `SAVE_SCHEMA_VERSION` |
| `L` | enum | `none` / `live` / `stale` | lock file + process probe | 写锁状态；`stale` 视为 `none` |
| `readable(x)` | bool | {true, false} | calculated | 文件存在、非空、可解析为存档结构 |
| `valid(x)` | bool | {true, false} | calculated | 在声明的 `version(x)` 对应 schema 下结构合法（不做玩法校验） |
| `version(x)` | int | 0–INT32_MAX | 文件 | 文件声明的 `schema_version`；0 只用于迁移测试夹具 |
| `migrate(x, a, b)` | SaveFile \| error | 迁移成功或失败 | calculated | 见下一条公式 |
| `load_outcome` | enum | 6 值 | calculated | `Fresh` / `Loaded` / `Migrated` / `Recovered` / `ReadOnly` / `Blocked` |

**Output Range:** 恰好六个值之一，无中间态。`Blocked` 与 `ReadOnly` 时 `writable = false`，任何写入请求返回对应结果而不创建临时文件。

**Example:** 主档版本 1、当前版本 1、结构合法、无锁 → `Loaded`。主档缺失、备份版本 1 合法（上次改名后崩溃）→ `Recovered`。主档版本 2、当前游戏版本 1 → `Blocked`，**不回退到版本 1 的备份**：静默使用旧备份会丢掉新版本写入的进度。另一实例持锁、主档可读且版本 ≤ 当前 → `ReadOnly`，允许浏览但不写入；旧版本用内存只读迁移渲染。

### 迁移链 `migrate`

The `migrate` formula is defined as:

`migrate(s, v_src, v_dst) = (m_{v_dst} ∘ … ∘ m_{v_src+1})(s)`

**Variables:**

| Variable | Type | Range | Source | Description |
|---|---|---|---|---|
| `s` | SaveFile | 任意合法旧档 | 文件 | 待迁移存档 |
| `v_src` | int | 0–`v_dst` | 文件 | 文件声明版本 |
| `v_dst` | int | `SAVE_SCHEMA_VERSION` | constant | 目标版本 |
| `m_k` | function | Save_v(k−1) → Save_v(k) | code + this GDD | 第 k 级迁移函数 |
| `migrate` | SaveFile \| error | 成功或 `MigrationError(k, field)` | calculated | 逐级迁移结果 |

**Output Range:** 成功时输出一个满足 `v_dst` 全部必填字段的存档；失败时输出 `MigrationError`，载入结果为 `Blocked`，原文件不被修改。每一步必须满足三条不变式：① 纯函数，不读时钟、不联网、不读运行期状态；② 补齐新字段的默认值，已有字段不丢；③ 不认识的顶层键移入或保留在 `extensions`。迁移只向上、不回退；`v_src > v_dst` 不是迁移，是 `Blocked`。

**Example:** MVP 版本为 1，正常迁移链为空。测试夹具使用一个合成的 `version = 0` 文件，其中 `wallet` 以字符串 `"120"` 存放；测试构建注册 `m_1` 把它解析为 int64 的 `120`，补齐 `career_id`、`slot_id = 0` 与空的 `records`，`extensions` 原样保留 → 输出版本 1、`Migrated`。若 `wallet` 为 `"abc"`，`m_1` 返回 `MigrationError(1, "progression.wallet")` → `Blocked`，文件不变。

### 存档体积上界 `save_bytes`

The `save_bytes` formula is defined as:

`save_bytes(s) = B_base + n_upg × U + n_sta × S + n_dish × D + n_rec × R + n_ms × M + ext_bytes`

**Variables:**

| Variable | Type | Range | Source | Description |
|---|---|---|---|---|
| `B_base` | int | 1024 B | constant | 信封：版本、career_id、时间戳、命名空间骨架 |
| `n_upg` | int | 0–12 | calculated | `progression.upgrade_levels` 条目数（含保留的未知 id） |
| `U` | int | 64 B | constant | 每条升级的 id + 等级 |
| `n_sta` | int | 0–5 | calculated | 已解锁档口数 |
| `S` | int | 96 B | constant | 每个档口条目 |
| `n_dish` | int | 0–40 | calculated | 已解锁菜品数 |
| `D` | int | 96 B | constant | 每个菜品条目 |
| `n_rec` | int | 0–5 | calculated | 按档口纪录行数 |
| `R` | int | 128 B | constant | 每行纪录（含冻结的历史事实） |
| `n_ms` | int | 0–40 | calculated | 已达成里程碑 id 数 |
| `M` | int | 48 B | constant | 每个里程碑 id |
| `ext_bytes` | int | 0–`SAVE_BYTES_MAX` | calculated | `extensions` 的原始字节数 |
| `SAVE_BYTES_MAX` | int | 262144 B (256 KiB) | constant | 单档硬上限 |
| `save_bytes` | int | 0–`SAVE_BYTES_MAX` | calculated | 估算的序列化体积 |

**Output Range:** 空生涯约 1.0 KiB；MVP 内容（12 菜、1 档口、3 升级）约 2.5 KiB；Full Vision 上限（40 菜、5 档口、12 升级、5 行纪录、40 里程碑）约 8.5 KiB。`save_bytes > SAVE_BYTES_MAX` 时拒绝写入并返回 `SaveTooLarge`，不截断、不丢弃条目——超限只能来自异常的 `extensions`，截断会静默丢数据。

**Example:** Full Vision 满载：`1024 + 12×64 + 5×96 + 40×96 + 5×128 + 40×48 = 1024 + 768 + 480 + 3840 + 640 + 1920 = 8672 B`，约 8.5 KiB，距离 256 KiB 上限有约 30 倍余量。

### 可用槽位 `slots_available`

The `slots_available` formula is defined as:

`slots_available = MAX_SLOTS − used_slots`

**Variables:**

| Variable | Type | Range | Source | Description |
|---|---|---|---|---|
| `MAX_SLOTS` | int | 1（MVP）–8 | constant | 槽位上限 |
| `used_slots` | int | 0–`MAX_SLOTS` | calculated | 已存在的生涯档数量 |
| `slots_available` | int | 0–`MAX_SLOTS` | calculated | 还能建立的生涯数 |

**Output Range:** MVP 恒为 `1 − used_slots`：首次启动前为 1，建立生涯后为 0。`slots_available = 0` 不是错误，是 MVP 的常态；界面不得显示「新建存档」入口（Core Rule 4）。放宽到多档时，只改 `MAX_SLOTS` 并补界面，不改信封格式。

**Example:** 首次启动：`1 − 0 = 1`。建立生涯并写入后：`1 − 1 = 0`。玩家删除生涯后回到 `1`。

## Edge Cases

- **If 主档与备份都不存在**：结果 `Fresh`，不报错——这是首次启动的正常路径。用默认值建立生涯（`wallet = 0`、空升级表、空解锁集、空纪录）；**写基线之前先调用解锁与档口的 `normalize()`，把回填后的 `unlocks` 并入同一基线事务**，不写空集合基线。写失败则保持 dirty 并提示，不阻塞进入菜单。
- **If 主档为空文件、截断或不是存档结构**：按损坏处理，尝试备份；不逐字段抢救。损坏的文件在玩家确认新建生涯前保持原样，不被覆盖。
- **If 主档缺失但备份存在**：结果 `Recovered`——上次写入在「主档改名备份」与「临时文件改名主档」之间崩溃。使用备份，并在下一次成功写入时重建主档。
- **If 主档损坏、备份版本较旧**：迁移备份后使用，`LoadReport` 必须写明「可能丢失最近一次成功写入之后的进度」，不得只说「已恢复」。
- **If 主档版本高于游戏版本**：`Blocked`。不回退到备份、不迁移、不覆盖。即使备份版本较低且可读，也不使用它——静默降级会丢数据。存活锁下只给「退出」「重试」；无存活锁时玩家可选择「新建生涯」（规则 21）。
- **If 主档与备份都无法读取**：`Blocked`，写入禁用，旧文件保留。**无存活写锁时**，只有玩家在界面明确选择「新建生涯」，两个文件才被改名为 `corrupt-<UTC>.sav` 隔离，随后建立新档；选择退出则文件原封不动。**`L = live` 时只给「退出」「重试」**，不提供「新建生涯」，避免隔离对方正在写的文件。
- **If 写盘中途失败（磁盘满、无权限、文件被占用）**：主档保持原样，临时文件删除，事务返回失败。购买类事务回滚内存并提示「未保存，购买未生效」；纪录类事务保留内存、标记 dirty、下一个时点重试。
- **If 写临时文件时崩溃**：临时文件不完整，下次启动被忽略并删除；主档与备份仍是一对完整副本。
- **If 主档改名备份后、临时文件改名主档前崩溃**：主档缺失、备份存在 → `Recovered`（见上）。
- **If 升级等级为 99 而 `max_level = 3`**：钳制到 3，写入 `LoadReport.warnings`，其余数据正常载入。不因单个字段越界拒绝整份存档。
- **If 升级等级为 -1**：按 0 处理并写入警告。**If 等级字段的类型不是整数**（字符串、浮点、布尔）：走损坏路径，不钳制——类型错误说明文件结构已经不成立。
- **If 存档含数据配置中不存在的 upgrade / dish / station id**：条目原样保留，运行期不生效，`LoadReport` 逐一列出。下次写盘原样写回，数据修好后恢复——不删除玩家的进度。
- **If `extensions` 含当前版本不认识的键**：原样保留并计数；不计入任何玩法逻辑。只有当 `save_bytes` 超限时才拒绝整次写入。
- **If 解锁集合为空**：结构合法，照常交付并报告 `EMPTY_UNLOCKS` 警告。是否回填免费档口由解锁与档口决定（见 Dependencies 的前置契约），存档不擅自添加。
- **If 钱包为负或接近 int64 极值**：原样往返，不钳制、不取绝对值。`9007199254740993` 这类超过双精度整数安全范围的值必须无损；若序列化格式做不到，该格式不可用（Open Question 2）。
- **If 旧档缺少 `records` 中的某个字段**：迁移补默认值（0 或空数组），不视为错误。缺少必填的信封字段（如 `schema_version`）才走损坏路径。
- **If `last_saved_at` 位于未来或早于 `created_at`**：界面照常显示，不据此做任何判断。时间戳不是逻辑输入。
- **If 同一用户启动第二个实例**：第二个实例读到存活锁且主档可读、版本 ≤ 当前 → `ReadOnly`，可浏览不可写；文件不可读或版本 > 当前 → `Blocked`（只给退出/重试）。第一个实例不受影响。锁的进程在崩溃后由存活探测 + 24 小时时间戳上限回收，无法判定时按存活处理。
- **If 玩家在 dirty 状态下退出**：先 `flush()`；成功则正常退出。失败则显示「进度可能未保存」并允许玩家仍退出——退出已经过确认，不能把玩家困在游戏里；磁盘上的旧档仍然完整。
- **If 玩家删除生涯**：二次确认后隔离旧文件、建立新档；设置文件不受影响。没有确认令牌的删除请求被拒绝。
- **If 玩家重置设置**：生涯档不受影响；设置与生涯是两个文件。
- **If 一局被放弃、进入失败或局中退出**：不产生任何写入；存档与进入本局前逐字段相同。
- **If 同一帧内先结算、后解锁**：仅当**结算本身**产生解锁变化时合并为同一事务；MVP/VS 中解锁只在菜单购买、且收据在结算 `commit` 之后才显示，因此两笔事务串行，不合并。其余情形按到达顺序串行写入，不交错。
- **If 数据配置尚未 `Ready` 就调用 `load()`**：返回结构化错误 `DataNotReady`，不读写任何文件。调用方负责在 `Ready` 之后调用。
- **If 玩家手工编辑存档**：按普通结构校验处理，不做防篡改。类型合法的新数值被接受（单机信任模型，Core Rule 25）；结构不合法走损坏路径，旧文件仍被保留。

**对未设计系统的前置契约（provisional）：**

| 系统 | 存档要求 | 若最终实现不同 |
|---|---|---|
| 局外升级 | 只提交完整的 `wallet` 与 `upgrade_levels` 新值，不提交增量；购买成交前必须等 `commit` 返回成功；钱包值必须能用 int64 表示 | 若提交增量，存档无法保证并发与回滚语义；事务边界会被拆散 |
| 解锁与档口 | 解锁集合只含 id；免费档口是否在集合内由它决定；载入后集合为空时必须能给出回填或明确不可玩的错误 | 若存档负责回填，会把玩法规则复制到持久层 |
| 纪录与里程碑 | `records` 字段由它定义；里程碑用稳定 id 而非序号；每局至多一次更新 | 若用序号，新增里程碑会改变历史含义 |
| 在线挑战 | 新增字段必须走 schema 版本迁移；不得要求存档在 MVP 写入 `challenges`；排行榜不得信任本地存档 | 若 MVP 就写 `challenges`，版本 1 的格式会被提前污染 |
| 界面流程 | 在 `Menu` 入口读取一次 `LoadReport`；`Blocked` 时禁用新建/购买入口，直到玩家明确选择；保存指示不打断操作 | 若界面自行猜测存档状态，会出现「显示已保存但磁盘未写」 |

**与数据配置的契约边界**：存档保存的是 id 与等级，不是记录本身。数据记录改了价格或上限，旧档仍然有效：载入时按 id 重新取记录，等级按新的 `max_level` 钳制。这正是数据配置规则 6「id 是契约」在持久层的落点——**发布后不能改名 id，否则存档里的引用会变成未知条目被冻结保留，而不是自动指向新记录**。

## Visual/Audio Requirements

**不适用。** 存档不绘制任何东西、不播放任何声音。它对玩家唯一可见的输出由界面流程实现：保存指示、恢复说明与写入失败提示。存档只提供状态与错误码，不规定颜色、动效或音色。

- 保存成功不需要音效；「已保存」的视觉反馈见 UI Requirements。
- 写入失败与 `Blocked` 的提示必须可读，不能只靠颜色（无障碍要求）。
- 是否需要失败音效由音效反馈决定；存档不拥有该事件。

## Game Feel

**目标手感是「不存在」。** 存档应当像呼吸一样不被注意：按下购买的那一帧，数字就该变；下次打开游戏，数字还在。任何「正在保存…」的等待、旋转图标或阻塞式弹窗都是在向玩家收税。

- **零等待**：购买与解锁的写盘在玩家可感知的交互完成之前发生，但不得让按钮出现可察觉的延迟；Full Vision 内容下单次写入预算 p95 ≤ 50 ms。
- **失败必须刺眼但不惊慌**：写盘失败不是玩家的错，提示要说清「什么没保存」，并给出可执行的动作（重试 / 继续）。不用红色警报覆盖整个屏幕。
- **恢复要说实话**：从备份恢复时，必须说明可能丢失了哪一次进度，而不是笼统的「已恢复」。信任一旦被含糊消耗，玩家下次就不敢相信「数字涨了」。
- **不做保存焦虑**：没有手动保存按钮，就没有「忘了存」的焦虑。玩家永远可以退出，最多丢掉尚未成功写入的那一次事务。

## UI Requirements

存档不拥有界面，但对界面流程拥有的屏幕提出约束：

1. **保存指示**：每次成功写入后显示一个短暂的「已保存」标记（约 1.5 秒后淡出），不阻塞输入、不移动布局、不发出声音。首次建立生涯与迁移写回同样显示。
2. **写入失败提示**：购买失败时，在购买控件旁给出「未保存，购买未生效」，并保持钱包与等级显示为未变后的值；纪录保存失败时给出「纪录可能未保存」，不打断结算页阅读。
3. **`ReadOnly` 说明**：另一实例持锁、文件可读且版本 ≤ 当前时，进入 `Menu` 后显示一次非模态说明，提供「以只读继续」与「退出」两个出口；只读期间隐藏购买/解锁入口，不提供「新建生涯」（避免隔离对方正在写的文件）。
4. **`Blocked` 说明**：进入 `Menu` 后显示一次模态说明，按原因给出口：
   - 「存档属于更新版本」：退出 / 新建生涯（旧档保留）。
   - 「存档与备份都无法读取」：退出 / 新建生涯（旧档保留）。
   - 「迁移失败」：退出 / 重试；不提供新建生涯（旧档有效，只是本版本读不了）。
   - 「另一个实例正在使用这份存档且文件暂不可读」：退出 / 重试（等待锁释放）；不提供新建生涯，避免隔离对方文件。
   **任何 `L = live` 的 `Blocked` 都只给退出/重试**，即使原因是「更新版本」或「无法读取」。
   不得提供「覆盖保存」。
5. **恢复说明**：`Recovered` 时显示一次非模态提示，写明来源（备份）与可能丢失的范围；玩家可关闭，不重复弹出。
6. **删除生涯**：入口放在设置或主菜单的二级位置，需二次确认，确认文案写明「旧档会被保留为隔离文件，可在文件目录中找回」。不得用单次点击删除。
7. **无手动保存入口**：MVP 不显示「保存游戏」「读取存档」「存档槽」任何控件（Core Rule 4）。
8. **无障碍**：所有提示同时用文字与图形表达，不只靠颜色；字号 150% 时不截断关键信息；模态说明可用键盘完成全部操作。

> **📌 UX Flag — 存档**：本系统有 UI 需求。Phase 4 写 epic 之前，先用 `/ux-design` 为保存指示、恢复提示、`Blocked` 模态与删除生涯确认出 UX 规格；相关 story 引用 `design/ux/` 下的对应规格，不直接引用本 GDD。

## Acceptance Criteria

每条都能由 QA 在不读本 GDD 的情况下独立执行。测试夹具放在 `tests/fixtures/save/`，每条用例使用独立目录，避免相互污染。所有涉及「崩溃」的用例使用可注入的写入失败点，不依赖真实杀进程。

**载入与首次启动**

1. **GIVEN** 用户目录下没有任何生涯档与备份，**WHEN** 启动游戏，**THEN** `LoadReport.outcome = Fresh`，内存中 `wallet = 0`、升级表为空、解锁集为空、纪录为空；进入 `Menu` 后立即写入一次基线，磁盘上出现主档且 `schema_version` 等于当前版本。
2. **GIVEN** 一个版本等于当前、结构合法的主档，**WHEN** 启动，**THEN** `outcome = Loaded`，`writable = true`，所有字段与文件逐项相等，且不产生新的备份文件。
3. **GIVEN** 主档缺失、备份存在且版本可迁移，**WHEN** 启动，**THEN** `outcome = Recovered`，使用备份内容，`LoadReport` 含「可能丢失最近一次成功写入之后的进度」；下一次成功写入后主档被重建。
4. **GIVEN** 主档版本 = 当前版本 + 1、备份版本 = 当前版本，**WHEN** 启动，**THEN** `outcome = Blocked`，`writable = false`，两个文件都未被修改，界面显示「存档属于更新版本」，且**没有**加载备份。
5. **GIVEN** 主档为零字节文件、备份不存在，**WHEN** 启动，**THEN** `outcome = Blocked`，主档未被覆盖；选择「新建生涯」后旧档改名为 `corrupt-<UTC>.sav`，新档建立；选择「退出」则文件逐字节不变。
6. **GIVEN** 主档与备份都是截断的 JSON 片段，**WHEN** 启动，**THEN** `outcome = Blocked`，不产生部分载入，不尝试逐字段抢救。
7. **GIVEN** 数据配置尚未 `Ready`，**WHEN** 调用 `load()`，**THEN** 返回 `DataNotReady` 错误，且磁盘上不产生任何新文件或修改时间变化。

**迁移**

8. **GIVEN** 测试夹具版本 0、`wallet` 以字符串 `"120"` 存放并含未知顶层键 `future_flag`，**WHEN** 载入，**THEN** `outcome = Migrated`，`wallet = 120`（int64）、`career_id` 与 `slot_id` 被补齐、`future_flag` 保留在 `extensions`，随后立即以当前版本写回磁盘。
9. **GIVEN** 同一版本 0 夹具中 `wallet = "abc"`，**WHEN** 载入，**THEN** 迁移返回 `MigrationError(1, "progression.wallet")`，`outcome = Blocked`，原文件逐字节不变。
10. **GIVEN** 一个已迁移并写回的文件，**WHEN** 再次启动，**THEN** `outcome = Loaded`（不再迁移），字段与上次写回后一致。

**写入与原子性**

11. **GIVEN** 已成功载入，**WHEN** 在写临时文件阶段注入失败，**THEN** 主档与备份的哈希均与操作前相同，临时文件被删除，`commit` 返回失败。
12. **GIVEN** 已成功载入，**WHEN** 在「主档改名备份」之后、「临时文件改名主档」之前注入崩溃并重新启动，**THEN** `outcome = Recovered`，载入的是崩溃前的最后一次成功内容。
13. **GIVEN** 一次结算同时更新钱包、纪录与**由结算本身产生的**解锁，**WHEN** 提交，**THEN** 磁盘上只发生一次事务写入；注入写失败时磁盘不发生写入，内存按规则 18 保留并标记 dirty（三者都重试），不回到事务前。MVP/VS 的菜单解锁是独立事务（购买策略，回滚），不并入结算。
14. **GIVEN** 一次购买成功后立即杀掉进程（不经过退出 flush），**WHEN** 重新启动，**THEN** 钱包与等级包含这次购买——购买在界面显示成功之前已经落盘。
15. **GIVEN** 写盘因磁盘只读而失败，**WHEN** 发起购买，**THEN** 界面显示「未保存，购买未生效」，钱包与等级保持原值，下一次启动也保持原值。
16. **GIVEN** 结算写盘失败，**WHEN** 查看本次结算页，**THEN** 纪录在界面上按新值显示并提示「纪录可能未保存」；下一次成功写入后，磁盘上的纪录与新值一致。

**版本、校验与未知条目**

17. **GIVEN** `max_level = 3` 而存档中某升级等级为 99，**WHEN** 载入，**THEN** 等级为 3、`LoadReport.warnings` 含该 id 与字段名，其余字段不受影响。
18. **GIVEN** 存档含 `upgrade_removed`、`dish_removed` 两个数据配置中不存在的 id，**WHEN** 载入并再次保存，**THEN** 两个 id 原样存在于新文件中，运行期不提供任何效果，`LoadReport` 列出它们。
19. **GIVEN** 存档 `wallet = 9007199254740993` 与 `wallet = -9223372036854775808`（两个夹具），**WHEN** 载入后保存再载入，**THEN** 两次读到的值都与原值逐位相等。
20. **GIVEN** 解锁集合为空、数据配置中存在 `unlock_cost = 0` 的档口，**WHEN** 载入，**THEN** `outcome = Loaded`、`writable = true`，`LoadReport` 含 `EMPTY_UNLOCKS` 警告，存档**没有**自行添加免费档口。

**边界与生命周期**

21. **GIVEN** 存档处于 `Clean` 状态、一局正在进行，**WHEN** 玩家确认放弃本局回到菜单，**THEN** 存档文件哈希与进入本局前相同，没有任何写入。
22. **GIVEN** 玩家在 `Paused` 中确认退出且存档 dirty，**WHEN** flush 因权限失败，**THEN** 显示「进度可能未保存」，玩家仍可退出，磁盘上的旧档完整可读。
23. **GIVEN** 同一个存档正被实例 A 持有写锁，**WHEN** 实例 B 启动，**THEN** B 的 `outcome = ReadOnly`、`writable = false`（主档可读），A 继续正常写入，B 不创建临时文件也不覆盖任何文件；**GIVEN** 主档在 A 的原子窗口内暂不可读，**THEN** B 的 `outcome = Blocked`、只提供「退出」与「重试」，不重命名任何文件。
24b. **GIVEN** 存活锁 + 主档版本 ≤ 当前，**WHEN** 实例 B 载入，**THEN** `outcome = ReadOnly`，用内存中的只读迁移渲染，不写盘；**GIVEN** 存活锁 + 主档版本 > 当前，**THEN** `outcome = Blocked`（版本过高优先于锁），只给退出/重试，不提供只读浏览。
24. **GIVEN** 一个遗留锁文件、其记录的进程已不存在且时间戳超过 24 小时，**WHEN** 启动，**THEN** 锁被回收，载入正常继续。
25. **GIVEN** 玩家确认删除生涯，**WHEN** 删除完成，**THEN** 旧档被改名为隔离文件而非删除，新档为默认值；设置文件逐字节不变。
26. **GIVEN** 同一份未改变的内存状态，**WHEN** 连续写入两次（排除 `last_saved_at`），**THEN** 两个文件逐字节相同，map 键顺序一致。

**性能与体积**

27. **GIVEN** Full Vision 满载夹具（40 菜、5 档口、12 升级、5 行纪录、40 里程碑），**WHEN** 计算 `save_bytes`，**THEN** 结果 ≤ 16384 B；把 `extensions` 填充到超过 256 KiB 时，写入被拒绝并返回 `SaveTooLarge`，原主档不变。
28. **GIVEN** 同一个满载夹具，**WHEN** 在最小规格 PC 的非调试构建上重复 100 次写入与载入，**THEN** 写入 p95 ≤ 50 ms、载入 p95 ≤ 100 ms；超预算时用同一夹具重测确认。
29. **GIVEN** 主档可读、版本 < 当前、迁移失败、备份合法，**WHEN** 载入，**THEN** `outcome = Blocked`，不加载备份，两个文件都未被修改。
30. **GIVEN** `Blocked`（迁移失败 / 持锁不可读），**WHEN** 玩家选择重试，**THEN** 调用 `retry_load()` 重新读取并替换缓存的 `LoadReport`，不隔离任何文件；若仍失败则停留在 `Blocked` 并允许再次重试。

> **测试夹具**：用例 8–10 需要测试构建注册一个 `m_1` 迁移函数与版本 0 的合成文件；用例 11–14 需要可注入的写入失败点与崩溃点；用例 16 需要一个会计数调用次数的纪录替身，用来证明重试发生在下一个写入时点。夹具不得修改真实的 12 道菜与升级数据。

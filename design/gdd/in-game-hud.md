# 局内 HUD（In-Game HUD）

> **Status**: In Design
> **Author**: user + Claude（autonomous 模式；Lean 模式不派生视觉子代理）
> **Last Updated**: 2026-11-03
> **Last Verified**: 2026-11-03
> **Implements Pillar**: 每口都是算术题 · 数字看得见地涨 · 时间在走，手不用快

## Summary

局内 HUD 是《回本》一局进行中唯一的常驻界面：它把回合、胃容量、实时净利与回本差额、当前波次的菜品卡、腻度与下一波预览同时摆在玩家眼前，让“这一口值不值”能在一屏内算完。它不拥有任何玩法数值——每一个数字都由对应系统发布，HUD 只负责读取、排版、合成与呈现。它存在的理由只有一个：支柱 4 要求每次决定后数字立刻可见地变化，而这份可见性必须由同一个地方统一提供，否则每个系统都会画出自己的半份真相。

> **Quick reference** — Layer: `Presentation` · Priority: `MVP` · Key deps: `餐局流程`（快照与信号）、`时间与回合`、`胃容量`、`菜品数值`、`腻度与口味`、`菜单波次`、`结算与入场费`、`输入`

## Overview

局内 HUD 是一块**只读仪表盘**。一局开始时它随着 `run_started` 亮起，把档口名、波次、回合槽位、容量条、净利与回本差额铺在屏幕边缘，把当前波的菜品卡放在中央的主操作区。玩家每提交一个动作，餐局流程广播 `action_committed`，HUD 在同一帧重新取一份完整快照并重绘；数字先变，动画后跟，动画永远不推迟数字。

它不计算任何东西。剩余回合来自时间与回合，容量与可吃性来自胃容量，价格与饱腹来自菜品数值，额外饱腹与解腻来自腻度与口味，波次与预览来自菜单波次，净利与回本差额来自结算与入场费，档口与流程态来自餐局流程。HUD 唯一“合成”的是呈现层：把这几份只读投影拼成一张卡、一行字、一根条。这条边界不是洁癖——同一局里出现两份净利求和，玩家迟早会看到两个不同的数字，而支柱 1 的前提是“算得清”。

它同样不拥有任何动作语义。吃哪道菜由玩家通过焦点选择，判定由餐局流程执行；跳过与结束取餐的代价由菜单波次拥有；暂停菜单、收据屏、菜单与升级界面都不属于它。它只提供**局内这一屏**，以及与其它界面交接时的进入/退出规则。

没有它，回合、容量、净利与波次会散落在四个互不知情的界面里；玩家要么凭记忆做算术，要么在结算页第一次看见入场费。它主要服务支柱 4「数字看得见地涨」，也服务支柱 1「每口都是算术题」与支柱 3「时间在走，手不用快」——压力来自屏上的格子，不来自反应速度，因此 HUD 里没有秒数、没有倒计时、没有限时确认。

## Detailed Design

### Core Rules

1. **职责边界**：本系统拥有**局内一屏的布局、信息层级、可见性、焦点与重绘节奏**。它不拥有：任何玩法数值或判定（回合、容量、价格、饱腹、腻度、净利、波次划分）、动作语义与提交顺序（餐局流程）、暂停菜单与收据屏（界面流程）、菜单、升级与设置（界面流程）、首局引导的讲解层（首局引导）、音效（音效反馈）。**HUD 写下的每一个数字都必须来自某个上游系统的公开读数，不得由 HUD 自行求和、推算或缓存为第二份真相。**

2. **只读投影**：HUD 对上游只有读操作。它不调用 `spend_turn()`、不调用 `consume()`、不推进波次、不结算、不改写任何状态。唯一的“写”是把玩家选中的焦点菜品随 `ui_accept` 交给餐局流程（见规则 14），以及把波次动作意图交给餐局流程（见规则 16）。

3. **单一快照，单一重绘**：HUD 在 `run_started`、`action_committed`、`run_ended`、`run_settled`、`run_faulted`、`run_discarded` 与 `frozen` 变化时，**读取一次**完整数据并构造一个不可变的 `HudFrame`；该帧内所有元素用同一份数据绘制。不允许一个元素读新快照、另一个元素还停在上一帧。两帧之间不轮询上游。

4. **同帧更新**：动作提交后，回合、容量、净利、回本差额与菜品卡状态必须在**提交后的第一个渲染帧**就显示新值。动画只能叠加在已经正确的新值之上（如数字跳动、卡片位移），不得用动画时长推迟数值变化，也不得先播动画再改数（支柱 4）。

5. **不自推结束**：HUD 不判断“回合耗尽”“放不下任何菜”“最后一波吃完”。它只读 `run_state` 与 `end_reason`；进入 `Ending` 的唯一依据是餐局流程的快照，不是 `turns_remaining = 0` 这类派生条件。HUD 不得自行弹出“时间到”模态。

6. **不自求和**：净利与回本差额只显示结算与入场费发布的 `running_net` / `shortfall`。计算口径、`entry_fee` 与取整都由结算拥有。**HUD 不得把菜品价格相加来得到净利**，即使结果在数学上相同——两份求和会在某个边界（空局、免单、错误局）漂移。

7. **不存在的数显示为 `—`，不显示 0**：快照未到达、上游返回错误、`run_state = Faulted` 时，受影响的数字显示 `—`，其余数字保持最后一次合法值并标为只读。把“不知道”画成 0 会让玩家把错误当成真实局面。

8. **菜品卡由 HUD 合成**：卡片的字段来自四个上游——名称与图标、价格、基础饱腹（菜品数值）；实际饱腹与 `+N` 追加、口味标签、解腻目标（腻度与口味）；可吃性 `can_fit` 与剩余容量（胃容量）；是否仍在当前可见集（菜单波次）。字段必须同屏，不得折叠进悬浮提示或详情页（菜品数值、腻度与口味的 UI Requirements）。

9. **不排序、不推荐、不隐藏**：菜品卡按菜单波次给出的当前可见集顺序陈列，不默认按价格、饱腹或单位价值排序；不提供“按可吃性隐藏”；不高亮“最优菜”；不在 HUD 任何位置显示 `unit_value` 或推荐解。允许玩家主动按价格或饱腹排序（菜品数值允许），但排序不改变默认顺序，也不得成为“答案排序”。

10. **不可吃态不是禁用控件**：`can_fit(d) = false` 的卡片置灰并写出“需要 X 格，剩 Y 格”，但它**仍可获焦、仍可悬停、仍可读全部字段**——它是信息，不是失效按钮。只有 `run_state ∈ {Ending, Settling, Handoff, Faulted}` 或 `frozen = true` 时，控件才真正禁用并不可获焦。这条规则把输入 GDD“禁用控件不可获焦”与胃容量 GDD“不可吃仍要写出原因”区分开：前者说的是流程禁用，后者说的是数据状态。

11. **不提交已知无效的动作**：焦点落在不可吃的卡上时，`ui_accept` 不向餐局流程提交动作；HUD 在该帧给出可见反馈（卡片抖动 ≤ 150ms + 焦点详情行写明“放不下”），不静默。若上游判定与 HUD 投影冲突（`can_fit = true` 但剩余容量显示不足），HUD 信任 `can_fit`，不提交动作，并在 `Faulted` 之外的调试构建中记录一次断言失败。

12. **回合显示没有时间维度**：HUD 只显示“剩余 / 总回合”的整数与可选槽位，不显示秒数、不显示预计剩余时间、不做逐秒递减、不做自动缩短的时间条。回合只在动作提交时变化（时间与回合规则 2、12）。

13. **容量条是唯一的进度条**：容量条显示 `capacity_used / capacity_total` 与剩余格数，条与数字同屏。它不做“按剩余容量是否可吃”的排序或自动过滤（胃容量 UI Requirements）。容量条在下一局从 `0 / 新总数` 重新开始，不保留上一局的残留数字或动画。

14. **焦点是 HUD 的产物**：键盘/手柄焦点与鼠标悬停是两条独立记录、分开绘制（输入规则 8）。HUD 把当前焦点（键盘焦点优先于悬停）解析为 `focused_dish_id`，随 `ui_accept` 一起交给餐局流程；餐局流程只校验该菜仍在可见集内，不自行猜焦点。**没有焦点时 `ui_accept` 不提交任何动作。**

15. **焦点顺序按屏幕位置**：上/下/左/右按卡片的屏幕位置导航，不按节点树顺序。每个 HUD 状态有初始焦点：`Active` 首帧落在当前波第一张可吃菜（若全不可吃则第一张卡）；最后一波结束取餐确认打开时落在「取消」。焦点不因重绘丢失；同一张卡在重绘后保持焦点。

16. **跳过与结束取餐由 HUD 呈现、菜单波次定义语义**：非最后一波显示「跳过本波 · 花 1 回合」，激活即提交，不再二次确认（代价已写在按钮上）；最后一波显示「结束取餐（免费）」，激活后打开 HUD 内的确认面板，面板默认焦点在「取消」。确认面板**不是**输入上下文意义上的 `Modal`——它不调用 `push_context(Modal)`（该接口的唯一调用方是界面流程），而是在 Run 上下文内做焦点陷阱：面板打开时导航限制在面板内，`ui_cancel` 关闭并把焦点还给原按钮。跳过与结束取餐都不得由 HUD 自行扣回合或丢菜，HUD 只提交意图。

17. **无倒计时、无限时确认**：任何确认面板都等待玩家输入，不会因为时间流逝自动关闭或自动确认（时间与回合规则 2；支柱 3）。

18. **数字格式固定**：金额为整数元，不显示小数，不使用千分位（HUD 金额最多 5 位）；净利总带符号（`+39` / `−46`），回本差额不带符号（`还差 46 元`）；回本后差额位置显示「已回本」而不是 0。回合写作 `剩余 6 / 10`；容量写作 `已用 12 / 20 格`；卡片不可吃原因写作 `需要 3 格，剩 2 格`。`unit_value` 不出现在 HUD。`run_seed` 只在 debug 构建显示。

19. **盈亏不能只靠颜色**：净利、回本差额、可吃性与跳过代价都必须同时有文字与符号。橄榄绿只用于容量条的安全区与正向变化，红色只用于负值强调，颜色永远是冗余通道而不是唯一通道。

20. **文案集中**：所有玩家可见字符串来自 HUD 的文本表，不散落在卡片节点或场景文本里；便于后续本地化替换，也便于验收时逐条核对。调试文本与正式文本分开。

21. **不拥有的界面与暂停路由**：暂停菜单、退出确认、收据屏、菜单、升级、设置、错误屏、首局引导的讲解气泡都不由 HUD 绘制。`ui_pause` 由场景与流程管理消费、暂停菜单与退出确认由界面流程绘制；HUD 不监听 `ui_pause`，只响应快照里的 `frozen`。HUD 只负责在 `frozen` 时降饱和并停止响应，在 `Settling` 时保持最终画面可见直到收据出现，在 `Handoff` 时淡出。谁绘制这些界面，谁负责它们的布局与输入。

22. **可测性**：HUD 的上游全部以接口注入（`run_state` provider、`running_net` provider、菜品/腻度/波次 provider、focus provider），不直接持有单例；给定一份 `HudFrame`，`format`/`layout` 层必须能脱离引擎在单元测试中产出确定的文本与矩形。视觉呈现本身用截图证据验收（见 Acceptance Criteria）。

**信息层级**（从高到低）：① 回合与容量（本局还能不能继续）→ ② 净利与回本差额（这一局赢没赢）→ ③ 菜品卡的价格与饱腹（下一口怎么选）→ ④ 波次与预览（还能等到什么）→ ⑤ 腻度细节（为什么贵了）。前两级必须在任何分辨率与任何字号下都不被遮挡；后三级可以在 150% 字号时换行或折叠成两行，但不得消失。

**导航顺序**：顶栏（只读，不可获焦）→ 菜品卡网格（按屏幕位置）→ 右栏操作按钮 → 循环回第一张卡。只读元素不进入焦点链；暂停菜单由界面流程接管焦点，HUD 不参与。

**信息分类原则**：常驻项是“随时会影响下一个决定”的数；条件项是“只有出现时才值得占屏”的数；隐藏项是“出现就会泄露答案或制造噪音”的数。HUD 没有“按需展开”的二级菜单——局内没有可暂停查看的详情页，暂停菜单属于界面流程，不承载 HUD 数据。

### States and Transitions

HUD 的状态是 `run_state` 的投影，加上一个独立的 `frozen` 维度。HUD 不新增玩法状态。

| HUD 状态 | 进入条件 | 可见 | 可交互 | 离开 |
|---|---|---|---|---|
| `Hidden` | `run_state = Idle`，或从未开局 | 无 | 无 | Run 场景挂载 → `Loading`；`run_started` → `Active` |
| `Loading` | Run 场景已挂载、`run_state = Initializing`、首个快照尚未到达 | 骨架：档口名、空槽位；数字显示 `—` | 无 | `run_started` → `Active`；初始化失败 → `Hidden`（错误屏由场景与流程管理绘制） |
| `Active` | `run_state = Active` 且 `frozen = false` | 全部信息块 | 吃菜、跳波、结束取餐、焦点导航 | `frozen` → `Frozen`；结束判定 → `Ending`；顶层离开 → `Hidden` |
| `Frozen` | `run_state = Active` 且 `frozen = true` | 全部信息块（降饱和 40%） | 无；暂停菜单在上层接管焦点 | `frozen = false` → `Active`；顶层离开 → `Hidden` |
| `Ending` | `run_state = Ending` | 全部信息块 + 结束原因横幅；数值冻结 | 无 | `run_settled` → `Settling` |
| `Settling` | `run_state = Settling` | 保持 `Ending` 最后一帧，直到收据出现的第一帧 | 无 | `Handoff` → 淡出 |
| `Handoff` | `run_state = Handoff` | 最后一帧淡出（≤ 200ms） | 无 | 完成 → `Hidden` |
| `Faulted` | `run_state = Faulted` 或 `run_faulted` | 最后一帧 + 错误横幅；受影响数字 `—` | 无 | 顶层离开 → `Hidden` |

**不变式**：

- `Active ↔ Frozen` 只由快照里的 `frozen` 翻转，HUD 不监听 `ui_pause`（该动作由场景与流程管理消费）。
- `Ending` 起 HUD 不再接受任何动作；`frozen = true` 时同样不接受。两者叠加时以更严格的为准。
- HUD 在 `Settling` 期间**不清屏**：收据由界面流程在同一位置覆盖上来，不能先清空 HUD 再显示收据（餐局流程 UI Requirements 6）。
- `run_discarded` 不会在一局从未开始时到达（餐局流程的边界）；收到后直接回 `Hidden`，不播放“结束”动画。

| 数据配置 | 间接上游 | 菜品与档口记录由菜品数值/菜单波次解析后传入；HUD 不直接查询数据目录 | 软（间接） |
| 界面流程 | 同级协调 | 屏幕归属：HUD 画局内一屏，界面流程画暂停菜单、收据、菜单、升级、设置；`frozen` 时暂停菜单在上层，`Settling` 时收据覆盖 HUD。无数据依赖 | 协调 |

| 音效反馈 | 下游（软） | 订阅 HUD 的焦点移动、确认、拒绝、跳过意图，用于 UI 音效；HUD 不播放音频、不拥有音效 | 软 |

**接口所有权**：

- 数值与判定归上游；HUD 只持有“这一帧画什么”。任何上游变化都不允许 HUD 猜。
- 焦点解析归 HUD；动作合法性归餐局流程。HUD 传 `focused_dish_id`，餐局流程校验它仍在可见集。
- 跳过/结束取餐的代价与可用性归菜单波次，HUD 只把文案与确认面板对着这组返回值画。
- 输入上下文归输入与请求方；HUD 不调用 `request_context` / `push_context` / `pop_context`。

## Formulas

> 本节定义的是**呈现层可测规则**：安全区、缩放、槽位数、对比度、面积预算与显示用的差额。它们不是玩法数值，不进入平衡表；但它们是可验收的硬约束，因此按公式写。所有布局值的权威存放点是 HUD 主题资源（Godot `Theme` / `HUDConfig`），代码里不写字面量。

### 安全边距 `hud_safe_margin`

`m = clamp(round(0.05 × H), 32, 96)`

**Variables:**

| Variable | Type | Range | Source | Description |
|---|---|---|---|---|
| `H` | int | 720–4320 | 运行时视口 | 视口高度（px） |
| `0.05` | float | — | constant | 安全边距占短边（高度）比例 |
| `32` / `96` | int | — | constant | 下限 / 上限（px） |

**Output Range:** 36 px @720p 到 96 px @2160p；窗口小于 1280×720 时按最低支持分辨率处理。**Example:** 1080p → `round(0.05 × 1080) = 54` px；1280×720 → 36 px。

### UI 缩放 `hud_ui_scale`

`s = clamp(min(W / 1280, H / 720), 1.0, 2.0)`

**Variables:**

| Variable | Type | Range | Source | Description |
|---|---|---|---|---|
| `W` / `H` | int | ≥1280 / ≥720 | 运行时视口 | 视口宽高（px） |
| `1280` / `720` | int | — | constant | 参考分辨率 |
| `1.0` / `2.0` | float | — | constant | 缩放上下限 |

**Output Range:** 1.0–2.0。**Example:** 1920×1080 → `min(1.5, 1.5) = 1.5`；2560×1080 → `min(2.0, 1.5) = 1.5`（超宽不放大，额外宽度给主区）；3840×2160 → `2.0`。

### 菜品卡列数 `hud_card_columns`

`n = clamp(floor((G + g) / (w_min + g)), 1, 4)`，其中 `g = 16 × s`，`w_min = 200 × s × τ`

**Variables:**

| Variable | Type | Range | Source | Description |
|---|---|---|---|---|
| `G` | int | ≥ 400 | 布局计算 | 主操作区可用宽度（px） |
| `s` | float | 1.0–2.0 | `hud_ui_scale` | UI 缩放 |
| `τ` | float | 1.0 / 1.25 / 1.5 | 无障碍字号设置 | 文本缩放 |
| `16` / `200` | int | — | constant | 卡片间距 / 卡片最小宽度（@100%） |
| `1` / `4` | int | — | constant | 列数上下限 |

**Output Range:** 1–4 列。**Example:** @1280×720，`s = 1`、`τ = 1`，`G = 912` → `floor((912 + 16) / (200 + 16)) = 4`；`τ = 1.5` → `w_min = 300` → `floor(928 / 316) = 2`（4 张卡排成 2×2）。卡片实际宽度 `w = (G − (n−1) × g) / n`；@1280 `τ=1` → `(912 − 48) / 4 = 216` px。

### 回合槽位 `hud_turn_slots`

`slots = min(turns_total, 12)`
`k = clamp(floor((B − (slots − 1) × gs) / slots), 8, 24)`

**Variables:**

| Variable | Type | Range | Source | Description |
|---|---|---|---|---|
| `turns_total` | int | 1–999 | 时间与回合（快照） | 本局总回合 |
| `B` | int | ≥ 200 | 布局计算 | 回合计数块宽度（px） |
| `gs` | int | 4 | constant | 槽位间距（px） |
| `12` | int | — | constant | 槽位绘制上限 |
| `8` / `24` | int | — | constant | 单槽宽上下限（px） |

**Output Range:** `slots ∈ [1, 12]`，`k ∈ [8, 24]`。**Example:** `turns_total = 10`、`B = 320` → `slots = 10`、`k = clamp(floor((320 − 36) / 10), 8, 24) = clamp(28) = 24` px，总宽 `10 × 24 + 9 × 4 = 276` px。`turns_total > 12` 时不画槽位，只画一根比例条 `remaining_ratio = turns_remaining / turns_total`，数字标签始终保留。

### 容量格 `hud_capacity_cells`

`cells = min(capacity_total, 24)`
`k = clamp(floor((C − (cells − 1) × gc) / cells), 6, 14)`
`fill_ratio = capacity_total > 0 ? capacity_used / capacity_total : 0`

**Variables:**

| Variable | Type | Range | Source | Description |
|---|---|---|---|---|
| `capacity_total` | int | 0–999 | 胃容量（快照） | 本局总容量 |
| `capacity_used` | int | 0–capacity_total | 胃容量（快照） | 已用格数 |
| `C` | int | ≥ 300 | 布局计算 | 容量条可用宽度（px） |
| `gc` | int | 2 | constant | 格间距（px） |
| `24` | int | — | constant | 格绘制上限 |
| `6` / `14` | int | — | constant | 单格宽上下限（px） |

**Output Range:** `cells ∈ [0, 24]`，`k ∈ [6, 14]`，`fill_ratio ∈ [0, 1]`。`capacity_total = 0` 时 `fill_ratio = 0` 并显示 `0 / 0`，不做除法、不显示 NaN。**Example:** `capacity_total = 20`、`C = 600` → `cells = 20`、`k = clamp(floor((600 − 38) / 20), 6, 14) = clamp(28) = 14` px；`capacity_used = 12` → `fill_ratio = 0.6`。

### 对比度 `hud_contrast_ratio`

`CR = (L1 + 0.05) / (L2 + 0.05)`
`L = 0.2126 × R_lin + 0.7152 × G_lin + 0.0722 × B_lin`
`c_lin = c / 12.92`（`c ≤ 0.03928`）或 `((c + 0.055) / 1.055) ^ 2.4`（否则）

**Variables:**

| Variable | Type | Range | Source | Description |
|---|---|---|---|---|
| `R/G/B` | float | 0–1 | HUD 主题 | 文本或背景的 sRGB 分量 |
| `L1` / `L2` | float | 0–1 | 计算 | 较亮 / 较暗颜色的相对亮度 |

**Output Range:** 1:1–21:1。验收阈值 `hud_contrast_min = 4.5`（constant）：所有 HUD 文本（含 ≥24px 大字号）≥ 4.5:1——比 WCAG 对大字号允许的 3:1 更严，以便全项目只用一条无障碍规则。**Example:** 白字 `#FFFFFF` 在 `#1F2A24` 面板上：`L1 = 1.0`、`L2 ≈ 0.0207` → `CR = 1.05 / 0.0707 ≈ 14.9:1`，通过。

### 常驻面积 `hud_area_usage`

`A = (W_top × H_top + W_rail × H_rail) / (W × H)`

**Variables:**

| Variable | Type | Range | Source | Description |
|---|---|---|---|---|
| `W_top` / `H_top` | int | — | 布局计算 | 顶栏宽高（不含安全边距） |
| `W_rail` / `H_rail` | int | — | 布局计算 | 右栏宽高 |
| `W` / `H` | int | — | 视口 | 视口宽高 |

**Output Range:** 0–1。验收阈值 `hud_persistent_area_max = 0.28`（constant）；`Active` 状态下必须 ≤ 0.28。**Example:** @1280×720：顶栏 `1208 × 72 = 86 976`，右栏 `280 × 560 = 156 800`，合计 `243 776 / 921 600 = 26.5%`，通过。**计量口径**：只计常驻信息块（顶栏 + 右栏）；菜品卡主操作区是玩法面，焦点详情行与瞬时确认面板不计入，另行按“不得遮挡前两级信息”验收。

### 不可吃差额 `hud_short_cells`（仅显示）

`short(d) = can_fit(d) ? 0 : max(0, effective_satiety(d) − capacity_remaining)`
`capacity_remaining = capacity_total − capacity_used`

**Variables:**

| Variable | Type | Range | Source | Description |
|---|---|---|---|---|
| `effective_satiety(d)` | int | 1–999 | 腻度与口味 | 该菜实际占用的格数 |
| `capacity_remaining` | int | 0–999 | 胃容量 | 剩余格数 |
| `can_fit(d)` | bool | — | 胃容量 | 权威可吃判定 |
| `short(d)` | int | 0–999 | 计算 | 卡片上“还差几格”的显示值 |

**Output Range:** `0 ≤ short(d) ≤ effective_satiety(d)`。**Example:** 菜需要 6 格、剩 4 格 → `short = 2`；卡片按上游要求的原文写「需要 6 格，剩 4 格」，焦点详情行补充「还差 2 格」。**这条公式只生成显示文案，不参与判定**；`can_fit` 与 `capacity_remaining` 冲突时以 `can_fit` 为准（规则 11）。

### 数值格式 `hud_number_format`

- 金额：`int` 元，无小数，无千分位（HUD 金额最多 5 位）；净利带符号（`+` / `−`，U+2212），差额不带符号。
- 回合 / 容量：`整数 / 整数`，两侧空格固定，便于字号放大时不跳动。
- 百分比（回本率）只出现在收据，不出现在 HUD。
- 所有数字右对齐或定宽等宽字体；数字位数变化时容器不重新排布（`min-width` 按 5 位数预留）。

### HUD 运行时不变式（断言，不是公式）

调试构建中，每帧构造 `HudFrame` 后校验以下五条；任一失败在日志中记录一次 `HUD_INVARIANT`，并在正式构建中保持最后一次合法渲染，不崩游戏。

| # | 不变式 | 失败含义 |
|---|---|---|
| 1 | `capacity_used + capacity_remaining = capacity_total` | 两个上游读数来自不同快照 |
| 2 | `turns_used = turns_total − turns_remaining` | 回合读数与总数不一致 |
| 3 | `shortfall = max(0, −running_net)` | 净利与差额不是同一口径 |
| 4 | `can_fit(d) = true ⇒ capacity_remaining ≥ effective_satiety(d)` | 可吃判定与剩余容量矛盾 |
| 5 | 本帧所有元素引用同一个 `run_id` 与同一个 `action_seq` | 跨帧混用了两份快照 |

### 调参起点（HUD 主题资源，不是平衡数值）

| 参数 | 起点值 | 安全范围 | 增加效果 | 减少效果 | 玩家可调 |
|---|---|---|---|---|---|
| 参考分辨率 | 1280×720 | 固定 | — | — | 否 |

| 右栏宽度 | 280 px | 240–360 | 预览与腻度更清楚，主区变窄 | 主区变宽，右栏需折行 | 否 |
| 卡片最小宽度 | 200 px | 180–240 | 列数减少，卡片更宽 | 列数增加，卡片更窄 | 否 |
| 卡片高度 | 176 px | 152–220 | 卡片信息更松 | 卡片更紧，需缩字号 | 否 |

## Edge Cases

- **If 第一帧快照尚未到达**：所有数字显示 `—`，不显示 0、不显示上一局残留值；骨架只画档口名与空槽位。`Loading` 状态不允许任何控件获焦。
- **If `turns_total > 12`**：不画逐格槽位，只画比例条与数字标签 `剩余 X / Y`；比例条不因总数变化而重新排布文字。玩家仍能从数字读到精确值。
- **If `capacity_total > 24`**：容量条只画前 24 格的视觉分段，其余以数字与比例条表示；数字 `已用 X / Y 格` 永远是精确值。
- **If `capacity_total = 0`**（数据损坏或极值）：容量条显示 `0 / 0`，`fill_ratio = 0`，不做除法；所有菜显示不可吃并给出“总容量为 0”的原因；这是错误态，不静默当成“吃不下”。
- **If `entry_fee = 0`（免单档口）**：开局 `running_net = 0`、`shortfall = 0`，差额位置显示「已回本」；不显示 `∞`、`NaN` 或 `100%`（结算 UI Requirements）。本局任何一道菜都保持「已回本」。
- **If 空局（0 道菜）进入结束**：HUD 保持最后画面，净利显示负数或 0（由结算给值），回本差额显示 `还差 N 元`；不出现空白表格或全 0 的伪造数据。
- **If `running_net` 或 `shortfall` 查询失败**：对应位置显示 `—`，HUD 其余部分照常；不回退到自己求和，不显示上一次的值冒充当前值。
- **If `run_faulted` 在 `Active` 中到达**：HUD 进入 `Faulted`，保留最后一帧布局、把受影响数字改为 `—`、在顶栏显示错误码文字；不播放结束动画、不自行跳转界面（跳转由场景与流程管理决定）。
- **If 同一帧内到达两个 `action_committed`**（理论上不应发生）：只渲染最后一个快照，不排队、不插值、不显示中间态；调试构建记录一次 `HUD_INVARIANT` 5。
- **If 暂停发生在数字动画中途**：动画立即停在当前位置，数字已经是新值；恢复后不重播、不补播。
- **If 窗口失焦 / 最小化**：不消耗回合（时间与回合规则 2）；HUD 不播放任何“回来后追帧”的动画，恢复时直接显示当前快照。
- **If 窗口被拉伸到超宽或超高**：安全边距按高度计算，右栏贴右、顶栏拉满宽度、主区居中并限制最大宽度 1600 px；不出现卡片被拉成细长条。
- **If 文本缩放切到 150%**：卡片列数按 `hud_card_columns` 降到 2 列，卡片高度增加；顶栏高度允许增至 96 px；任何文字不截断、不覆盖相邻元素。若仍放不下，右栏内容折成两行，信息块不消失。
- **If 手柄断开**：焦点保持在最后一张卡上并继续绘制；不重置到第一张、不清空焦点；下一个方向输入或鼠标悬停重新定位。HUD 不显示设备错误（由场景与流程管理处理）。
- **If 焦点菜在重绘后已不在可见集**（被吃掉或跳波）：焦点移到同一位置的下一张卡；若当前波为空且已自动推进，焦点落到新波第一张可吃菜。
- **If 当前波全部不可吃**：卡片全部置灰并各自写出原因；焦点仍可移动，`ui_accept` 只给“放不下”反馈；跳过按钮保持可用——HUD 不自行结束本局，也不提示“无菜可吃”（那是菜单波次与餐局流程的判定）。
- **If 最后一波点「结束取餐」**：打开确认面板，逐条列出当前波仍会失去的菜，并以「另有 N 道本局剩余」汇总不可见的部分；确认面板不假装知道未揭晓的内容。默认焦点在「取消」，`ui_cancel` 关闭并还原焦点。
- **If 非最后一波点「跳过本波」**：立即提交，不弹确认；按钮文案已写明代价。若处于 `turns_remaining = 0` 的终局帧（餐局流程尚未切到 `Ending` 的那一帧），按钮置为不可用并写明“没有回合了”，不提交、不静默。
- **If 跳过或吃菜被餐局流程拒绝**：HUD 不乐观更新任何数字；保持旧值，焦点详情行显示一行拒绝原因（来自 `run_flow` 的结构化错误），150 ms 后恢复常态文案。
- **If `run_discarded` 在 `Frozen` 中到达**：直接回 `Hidden`，不播放收尾动画，不显示“本局结束”；被丢弃的局没有收据。
- **If 首局引导压入 Blocked 上下文**：HUD 的回合、容量、净利数字仍然可见（餐局流程 UI Requirements 7）；引导层由首局引导绘制，HUD 只提供被讲解控件的位置信息（矩形还是锚点 id 见 Open Question 8），不改变自己的布局。
- **If 玩家把 HUD 不透明度降到最低**：数字文本仍保持最低对比度要求（由面板底色不透明度下限保证）；不允许出现“透明到读不清”的设置组合。
- **If 中文长菜名超过卡片宽度**：最多两行，第二行以省略号结束；完整名称在焦点详情行显示。不从中间截断数字。

## Visual/Audio Requirements

**视觉方向**：沿用概念文档的锚点「食堂价目板 + 橄榄绿安全区」。HUD 不是科幻仪表盘，也不是手游浮层——它应该像一块印在托盘纸上的价目板：浅色纸面底、深色等宽数字、细线分隔、圆角很小。视觉密度服务于“一眼读完四个数”，不服务于装饰。

- **色彩语义**：橄榄绿 `#6F7D3F` 只表示“容量安全 / 正向变化”；砖红 `#A6402F` 只表示“负值 / 放不下”；墨色 `#1F2A24` 为正文；纸色 `#F2EDE3` 为面板底。所有颜色语义同时有文字或符号冗余。
- **数字优先**：金额与回合使用等宽数字字体，字号 ≥ 28 px；标签（“剩余”“已用”“还差”）比数字小一档，颜色更淡。数字与标签的基线对齐，不出现数字跳动导致整行位移。
- **卡片**：卡片是一张“小票条目”——左上名称、右上价格、中部饱腹与追加、底部口味标签与解腻标记；不可吃时整卡降到 40% 不透明度并加一条 2 px 左边界提示线，原因文字保持 100% 不透明，不能被一起置灰到读不清。
- **容量条**：横向分段条，已用为橄榄绿实心、剩余为空心描边；`capacity_used` 逼近 `capacity_total` 时不变红——本游戏没有“危险容量”，满了只表示放不下下一道菜，不是失败。
- **动效预算**：数字变化 ≤ 250 ms 的位移/放大回落；卡片获得焦点 ≤ 120 ms 的描边加粗；拒绝反馈 ≤ 150 ms 的横向抖动；确认面板 ≤ 180 ms 的淡入。所有动效在“减少动态”开启时替换为瞬时状态切换。
- **层级与遮挡**：主区卡片永远不被右栏或顶栏覆盖；确认面板居中并带 60% 暗底，但确认面板之外的 HUD 数字仍然可读（不能整屏糊掉，玩家需要看着数字决定是否结束）。
- **无 VFX、无粒子、无屏幕震动**：本系统是信息层，不是反馈特效层；强调靠排版、对比与短促位移，不靠特效。

**音频**：本系统不播放音频。焦点移动、确认、拒绝、跳过的音效由音效反馈系统订阅 HUD 事件后播放；HUD 只负责发出这些事件，不持有音频资源，也不决定音色。

## Game Feel

- **即时**：动作提交 → 数字变化发生在同一帧；玩家按下的那一刻就应该看到回合减一、容量条前进、净利上升。任何“等动画播完再改数”都算违反支柱 4。
- **可预期**：同一个焦点位置、同一个按键，永远提交同一道菜；焦点不会因为一次重绘跳到别处。跳过与结束取餐的按钮位置固定，不随净利正负或波次内容移动。
- **不催促**：没有倒计时、没有秒表、没有“思考超时”；玩家可以盯着一屏数字算多久都行。唯一的压力来自格子数量本身。
- **拒绝要看得见**：放不下、没回合、已结束——每一种“按了但没发生”都必须有文字反馈，且反馈位置靠近焦点，不弹整屏模态。
- **收尾要稳**：结束的那一帧，最后吃下的菜、最终净利与剩余容量仍然停在屏幕上，直到收据覆盖上来；不闪白、不清屏、不提前隐藏数字。
- **焦点手感**：方向导航一卡一步，按住超过输入 GDD 的重复延迟后才连续移动；鼠标悬停不抢键盘焦点，键盘导航也不清掉悬停高亮。两种焦点用不同视觉（键盘为实线描边，悬停为浅色底），玩家能同时看到“我将要按的”和“我的鼠标在哪”。

## UI Requirements

> **📌 UX Flag — 局内 HUD**：本系统就是 UI 系统，且 `design/ux/hud.md` 尚未存在。在 Phase 4（Pre-Production）写 epic 之前，必须先用 `/ux-design` 为局内 HUD 产出 UX 规格；相关 story 引用 `design/ux/hud.md`，不直接引用本 GDD。本 GDD 只记录对 UX 规格的约束，不假设规格已完成，也不创建 UX 文件。

UX 规格必须覆盖以下内容，并以本 GDD 的 Formulas 作为数值下限：

1. **屏幕状态**：`Loading` / `Active` / `Frozen` / `Ending` / `Settling` / `Handoff` / `Faulted` 七种局内 HUD 状态的完整视觉稿与转场；`Hidden` 是“无画面”状态。
2. **布局与安全区**：1280×720 参考稿 + 1920×1080 + 2560×1080 + 150% 字号四组；每组标注安全边距、顶栏、右栏、卡片网格的实际矩形。
3. **组件规格**：顶栏（波次条、回合槽、净利/差额、容量条）、菜品卡（可吃/不可吃/焦点/悬停/解腻标记）、焦点详情行、腻度面板、下一波预览、跳过/结束取餐按钮、结束取餐确认面板、结束原因横幅、错误横幅。
4. **信息优先级**：本 GDD 的“信息层级 ①–⑤”在 UX 稿上必须可指认；任何遮挡必须能说明遮挡的是 ④/⑤ 而不是 ①/②。
5. **焦点与导航**：焦点链顺序、初始焦点、焦点陷阱（结束取餐确认）、鼠标悬停与键盘焦点的双轨视觉、手柄与键鼠切换时的焦点保持。
6. **数字格式与空值**：`+39` / `−46` / `还差 46 元` / `已回本` / `—` / `0 / 0` 六种文本形态的排版样例。
7. **无障碍**：对比度 ≥ 4.5:1 的实测表（每个文本/背景组合一行）、150% 字号的重排规则、减少动态替换表、HUD 不透明度与文本缩放两个玩家设置的影响范围、颜色之外的第二通道。
8. **文案表**：所有按钮、标签、原因、空状态、错误态的正式中文文案，以及每条文案的字符上限（超出时如何折行）。
9. **与其它界面的交接**：暂停菜单覆盖 HUD 时的 z 序与降饱和程度；收据出现时 HUD 保留到哪一帧；首局引导气泡与卡片锚点的相对位置。

**不归 UX 规格决定的**（由本 GDD 与上游 GDD 决定）：哪些数字显示、数字的口径与来源、可吃性判定、跳过与结束取餐的代价、结束原因枚举、动作提交时机。

## Acceptance Criteria

> **覆盖说明**：`hud_safe_margin` 由「布局与视觉预算」的安全边距判据覆盖；`hud_ui_scale` 由超宽屏判据；`hud_card_columns` 由 150% 字号列数判据；`hud_turn_slots` 由回合槽位判据；`hud_capacity_cells` 由容量格判据；`hud_contrast_ratio` 由对比度判据；`hud_area_usage` 由常驻面积判据；`hud_short_cells` 由不可吃原因判据；`hud_number_format` 由数字格式化判据。运行时不变式由「数据投影与不计算」的全量校验判据与 `can_fit` 冲突判据覆盖。其余判据来自 Detailed Design。

**数据投影与不计算**

1. **GIVEN** 一局已开始且已吃过 3 道菜（16、5、18 元），**WHEN** HUD 显示净利，**THEN** 显示 `−46` 且与结算的 `running_net` 完全一致；HUD 代码路径中不存在价格求和。
2. **GIVEN** 一局刚开始、尚未吃任何菜，**WHEN** `run_started` 到达，**THEN** 净利显示 `−entry_fee`（MVP 食堂档口为 `−85`）、回本差额显示 `还差 entry_fee 元`（MVP 为 `还差 85 元`），不需要等第一道菜。
3. **GIVEN** `turns_remaining = 0`，**WHEN** 快照更新但 `run_state` 仍为 `Active`，**THEN** HUD 不显示“时间到”模态、不进入 `Ending`、只把数字画成 `剩余 0 / 10` 并等待餐局流程的结束信号。
4. **GIVEN** 结算的 `running_net` 查询返回错误，**WHEN** HUD 重绘，**THEN** 净利与差额位置显示 `—`，不显示 0、不显示旧值、不自行求和。
5. **GIVEN** 同一帧到达两个 `action_committed`，**WHEN** HUD 重绘，**THEN** 只渲染最后一个快照，不出现两个中间态；调试构建记录一次 `HUD_INVARIANT` 5。
6. **GIVEN** `run_faulted` 在 `Active` 中到达，**WHEN** HUD 进入 `Faulted`，**THEN** 保留最后一帧布局、受影响数字为 `—`、顶栏显示错误码文字、无控件可获焦。
7. **GIVEN** `run_discarded` 在 `Frozen` 中到达，**WHEN** HUD 收到信号，**THEN** 直接进入 `Hidden`，不播放结束动画、不显示收据。
8. **GIVEN** 一份合法快照，**WHEN** 校验五条运行时不变式，**THEN** 全部成立；人为注入 `capacity_used + remaining ≠ total` 时，调试构建恰好记录一次 `HUD_INVARIANT` 1。

**布局与视觉预算**

9. **GIVEN** 视口 1280×720，**WHEN** 计算安全边距，**THEN** 结果为 36 px；视口 1920×1080 时为 54 px；2160p 时为 96 px（不超出上限）。
10. **GIVEN** 视口 2560×1080，**WHEN** 计算 UI 缩放，**THEN** 结果为 1.5；字号不因超宽而放大，主区获得额外宽度。
11. **GIVEN** 1280×720 与 100% 字号，**WHEN** 4 张卡排布，**THEN** 列数为 4、卡宽 216 px；切到 150% 字号后列数为 2，文字不截断、不覆盖。
12. **GIVEN** `Active` 状态，**WHEN** 计算常驻面积，**THEN** 顶栏 + 右栏面积 ≤ 28%；1280×720 下实测为 26.5%。
13. **GIVEN** `Active` 状态，**WHEN** 统计同时可见的信息块，**THEN** 恰为 8 个（波次、回合、净利/差额、容量、菜品卡、腻度、预览、操作区），无第九块。
14. **GIVEN** `turns_total = 10`，**WHEN** 绘制回合槽位，**THEN** 画 10 个槽、单槽 24 px、总宽 276 px，并同时显示 `剩余 6 / 10`；`turns_total = 20` 时不画槽位，只画比例条与数字。
15. **GIVEN** `capacity_total = 20`、`capacity_used = 12`，**WHEN** 绘制容量条，**THEN** 20 格、单格 14 px、`fill_ratio = 0.6`，并同时显示 `已用 12 / 20 格`。
16. **GIVEN** 屏幕中央 40% 区域，**WHEN** 检查 `Active` 布局，**THEN** 该区域内只有可交互的菜品卡与瞬时确认面板，没有任何非交互 HUD 元素。

**数字与文案**

17. **GIVEN** 以下数值，**WHEN** 格式化，**THEN** 分别显示：`running_net = 39 → +39`；`running_net = −46 → −46`（U+2212）；`shortfall = 46 → 还差 46 元`；`shortfall = 0 → 已回本`；回合 `6/10 → 剩余 6 / 10`；容量 `12/20 → 已用 12 / 20 格`；`turns_total = 0 → 剩余 0 / 0`。
18. **GIVEN** 一道菜 `effective_satiety = 6`、`capacity_remaining = 4`、`can_fit = false`，**WHEN** 显示卡片，**THEN** 卡片置灰、写「需要 6 格，剩 4 格」、原因文字仍为 100% 不透明、仍可获焦。
19. **GIVEN** 一道菜 `can_fit = true` 但 `capacity_remaining < effective_satiety`（人为注入矛盾），**WHEN** 玩家激活该卡，**THEN** HUD 信任 `can_fit`，不提交动作，调试构建记录 `HUD_INVARIANT` 4。
20. **GIVEN** 一局进行中，**WHEN** 检查整块 HUD 的可见文本，**THEN** 不出现 `unit_value`、`元/格`、推荐顺序、最优解或任何排序建议。

**卡片、波次与操作**

21. **GIVEN** 当前波 4 道菜，**WHEN** HUD 渲染，**THEN** 4 张卡按 `visible_dishes` 顺序陈列，不按价格、饱腹或单位价值排序；无默认排序控件被激活。
22. **GIVEN** 一张卡被焦点选中，**WHEN** 玩家按 `ui_accept`，**THEN** HUD 把该卡 id 随动作提交给餐局流程，餐局流程校验其仍在可见集；HUD 不自行扣回合或改容量。
23. **GIVEN** 焦点落在不可吃的卡上，**WHEN** 玩家按 `ui_accept`，**THEN** HUD 不提交动作，卡片抖动 ≤ 150 ms 并在焦点详情行写出“放不下”。
24. **GIVEN** 非最后一波，**WHEN** 玩家激活「跳过本波 · 花 1 回合」，**THEN** HUD 立即提交跳波意图，不弹二次确认；回合数字由随后的 `action_committed` 在同一帧更新。
25. **GIVEN** 最后一波，**WHEN** 玩家激活「结束取餐（免费）」，**THEN** 打开 HUD 内确认面板，逐条列出将失去的当前波菜品，默认焦点在「取消」；`ui_cancel` 关闭并把焦点还原到按钮；确认后面板关闭并提交意图。
26. **GIVEN** 最后一波且 `turns_remaining ≥ 1`，**WHEN** 渲染「结束取餐」，**THEN** 按钮可用且文案写明免费；**GIVEN** 非最后一波的 `turns_remaining = 0` 终局帧，**WHEN** 渲染「跳过本波」，**THEN** 按钮不可用并写明“没有回合了”。

**无障碍**

27. **GIVEN** HUD 上每一组文本/背景组合，**WHEN** 用 `hud_contrast_ratio` 实测，**THEN** 全部 ≥ 4.5:1，包括 ≥24 px 的大字号。
28. **GIVEN** 移除颜色的灰度截图，**WHEN** 检查净利、回本差额、可吃性、跳过代价，**THEN** 每一项仍能通过文字与符号（`+`/`−`/原因句/代价句）读出含义，颜色不是唯一通道。
29. **GIVEN** 文本缩放 150%，**WHEN** 检查顶栏、卡片、右栏、确认面板，**THEN** 无文字溢出容器、无相邻元素重叠、无信息块消失；卡片降为 2 列。
30. **GIVEN** 开启“减少动态”，**WHEN** 触发数字变化、焦点移动、拒绝反馈、确认面板，**THEN** 全部为瞬时状态切换，无位移、无抖动、无淡入。
31. **GIVEN** HUD 不透明度设为最低档，**WHEN** 检查数字文本，**THEN** 对比度仍 ≥ 4.5:1，不存在“透明到读不清”的组合。
32. **GIVEN** 任意确认面板，**WHEN** 等待 60 秒不操作，**THEN** 面板不会自动关闭或自动确认。

**状态与焦点**

33. **GIVEN** `frozen = true`，**WHEN** 玩家尝试吃菜、跳波或结束取餐，**THEN** 全部控件不可获焦、不提交动作，HUD 降饱和 40%，暂停菜单在上层且 HUD 不自绘暂停菜单。
34. **GIVEN** `run_state = Ending`，**WHEN** HUD 重绘，**THEN** 显示结束原因文字横幅、所有控件禁用、最后画面保持可见，直到收据出现。
35. **GIVEN** `Active` 首帧，**WHEN** 建立初始焦点，**THEN** 焦点落在当前波第一张可吃菜；若全部不可吃则落在第一张卡。
36. **GIVEN** 当前焦点卡被吃掉，**WHEN** 下一帧重绘，**THEN** 焦点落在原位置的下一张卡，不跳回第一张；当前波变空时落到新波第一张可吃菜。
37. **GIVEN** 鼠标悬停与键盘焦点在不同卡上，**WHEN** 玩家移动鼠标，**THEN** 键盘焦点不变；键盘导航时悬停高亮也不清除；两种焦点用不同视觉同时可辨。
38. **GIVEN** 手柄在 `Active` 中断开，**WHEN** HUD 重绘，**THEN** 焦点保留在最后一张卡，无错误重置、无设备错误横幅。

**性能与证据**

39. **GIVEN** `Active` 状态且无动画在播，**WHEN** 观察连续 60 帧，**THEN** HUD 不轮询上游、不重建 `HudFrame`，开销 ≤ 0.5 ms/帧 @1080p。
40. **GIVEN** 一个动作提交，**WHEN** 记录提交帧与数字变化帧，**THEN** 两者为同一渲染帧；动画时长不影响数字可见时间。
41. **GIVEN** 实现完成，**WHEN** 关闭验收，**THEN** `production/qa/evidence/` 中存在以下保留截图：720p `Active`、1080p `Active`、150% 字号、`Frozen`、`Ending`、最后一波确认面板、不可吃卡、错误态、深色与浅色背景下的对比度样例。

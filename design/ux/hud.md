## 1. HUD Philosophy

**这是一张摊在托盘上的价目单，不是仪表盘。**《回本》让玩家盯着的不是世界，是账本：这一口涨了几元、还差几元、还剩几格、还剩几回合。因此本作的 HUD 不属于“信息越少越沉浸”的流派——恰恰相反，**信息密度就是玩法本身**（对照 art bible § 1“价格与饱腹值永远最大声”）。但密度不等于自由：HUD 是一块**只读**的排版层，它只把上游已经发布的数字排好、拼好、在同一帧画出来；一旦它开始自己求和、自己推算结束、自己排序，屏幕上就会出现第二本账，而支柱 1「每口都是算术题」的前提是**只有一本账**（`HUD-R1`、`HUD-R6`）。所以哲学可以压成两句话：**该看的数一个都不许少，不该算的数一个都不许算。**

**Visibility principle — 默认常驻（SHOW），例外只有两类。** 常驻的八个信息块（波次、回合、净利/差额、容量、菜品卡、腻度、预览、操作区）在 `Active` 期间任何状态下都可见（`HUD-AC13`）；“条件显示”只用于**由焦点或状态触发才有意义**的东西：详情行（有焦点才显示）、不可吃原因（不可吃时才写）、解腻预览（选中解腻菜时才写）、下一波预览（`menu_vision > 0` 且非最后一波）、确认面板与结束/错误横幅。**没有任何信息藏在悬浮提示或二级页里**——局内没有可暂停查看的详情页（`HUD-R8`、`DISH-UI`），暂停菜单归界面流程且不承载 HUD 数据（`HUD-R21`）。

**The Rule of Necessity（必要性法则）**：一个 HUD 元素只有在 **“缺了它，玩家必须离开这一屏去找同一个数，或会由此做出可测量的更差决定”** 时才配占屏。反向也成立：**任何“替玩家算好答案”的元素都不配占屏**——`unit_value`、推荐顺序、最优解、有效单位价值排序一律不得出现（`HUD-R9`、`HUD-R18`、`DISH-UI`、`SETT-R12`、`ONB-R13`）。这条法则是本 HUD 拒绝加元素的唯一 veto 依据，也是“加个排序按钮吧”这类请求的答复模板。

**密度声明与自检**：本 HUD 的 Must Show 清单是 8 个信息块，常驻面积预算 28%（`HUD-F:hud_area_usage`，1280×720 实测 26.5%）。这与“信息密集”哲学一致，不存在“哲学说极简、清单却在膨胀”的冲突；冲突点在相反方向——**每次有人想加第九块，都必须先说出它要挤掉哪一块**（见 § 7）。

### 2.2 Categorization

| 信息 | 常驻 | 条件 | 按需 | 隐藏 / 世界 | 理由 |
|---|---|---|---|---|---|
| 回合（数字 + 槽位） | X | | | | 每一个吃菜/跳波决定都要先问“还剩几格”，不常驻就只能靠记忆（`TURN-UI`） |
| 容量（条 + 整数读数） | X | | | | 可吃性判据必须与价格同屏，否则算术题在下单前算不完（`STOM-UI`） |
| 净利 `running_net` | X | | | | 开局即 `−85`，否则玩家在收据上第一次见到入场费（`SETT-UI`） |
| 回本差额 `shortfall` | X | | | | 它是本作唯一的“赢了没有”读数（支柱 1/4） |
| 当前波索引 / 总波数 | X | | | | 波次决定还能等到什么，是取舍的一半 |
| 未揭晓波 `?` 槽与菜数 | X | | | | `?` 制造好奇；数量是玩家唯一能拿到的供给信息（`WAVE-R3`） |
| 菜品卡（价格、饱腹、`+N`、标签） | X | | | | 主操作面；字段必须同屏不折叠（`HUD-R8`） |
| 不可吃原因 | | X | | | 只有不可吃时才值得占字；常驻会把正常卡也写满（`STOM-UI`） |
| 解腻标记 | | X | | | 只对标了解腻的菜有意义 |
| 解腻目标与 `−1` 预览 | | X | | | 选中解腻菜才需要；不选中时写出来是噪音（`CLOY-UI`） |
| 腻度组计数 | X | | | | 它是“为什么这道贵了”的唯一解释；空组不占屏（`CLOY-UI`） |
| 下一波预览 | | X | | | `menu_vision > 0` 且非最后一波才存在（`WAVE-R7`） |
| 跳过 / 结束取餐按钮与代价 | X | | | | 唯一的“不吃”出口；代价必须前置写在按钮上（`WAVE-UI`） |
| 焦点详情行 | | X | | | 有焦点即显示；它是卡片的放大镜，不是第二块面板 |
| 结束原因 | | X | | | 只在 `Ending` 起出现，且必须用文字（`RUN-UI 8`） |
| 冻结 | | X | | | 全屏降饱和 + 暂停菜单覆盖；HUD 不自绘暂停菜单（`HUD-R21`） |
| 错误码 | | X | | | 仅 `Faulted`；release 只给一句人话，码只在 debug |
| 焦点 / 悬停 | | X | | | 输入产生的瞬时状态 |
| `run_seed` | | | | X | 泄漏解谜（刷种子），仅 debug 显示 |
| `unit_value` / 有效单位价值 | | | | X | 它就是答案；只在收据（`DISH-UI`、`ONB-R13`） |
| 推荐顺序 / 最优解 | | | | X | 禁止生产，也禁止展示（`SETT-R12`） |
| 入场费、钱包、升级、纪录、存档 | | | | X | 属于主菜单/升级/纪录/收据，局内重复会变成第二本账 |
| 键位说明 | | | | X | 首局引导讲一次；HUD 画键位会与手柄/键盘双设备冲突（`INP-OQ2`） |
| 音效 | | | | X | 听觉通道；每一条都有视觉对应物（`AUD`） |

**分类原则**：常驻项是“随时会影响下一个决定”的数；条件项是“只有出现时才值得占屏”的数；隐藏项是“出现就会泄露答案或制造噪音”的数。**本 HUD 没有“按需展开”（On Demand）一级**——局内没有可暂停查看的详情页，暂停菜单属于界面流程且不承载 HUD 数据（`HUD-R21`、信息清单“信息分类原则”）。这一列全空是设计决定，不是遗漏。

**聚合完整性说明**：`systems-index.md` 中有 UI 需求的系统共 11 个。本清单覆盖了会进入局内 HUD 的 8 个（时间与回合、胃容量、菜品数值、腻度与口味、菜单波次、结算与入场费、餐局流程、输入），并逐一记下其余系统的界面归属（界面流程、局外升级、纪录与里程碑、解锁与档口、存档、音效反馈、首局引导、场景与流程管理、数据配置）。`数据配置` 无独立界面：它经菜品数值/菜单波次解析后到达，HUD 不直接查询（`HUD` Dependencies）。**没有“无 UI 需求”的系统被静默排除**。

**与模板的区域规则有一处刻意偏离**：模板要求“中央 40% 保持空白”，本 HUD 的中央 40% 正好落在 **B 主操作区**上，里面是可交互的菜品卡。理由是**本作没有世界**——没有角色要走、没有敌人要躲，“中央”不是视野焦点而是**账本正文的位置**。因此中央区的规则改为：**中央 40% 只允许“可交互的菜品卡”与“瞬时的结束取餐确认面板”**，任何只读信息块（波次、回合、净利、容量、腻度、预览）不得进入；这条由 `HUD-AC16` 直接验收。

**4.2.1 波次条**

- 视觉描述：横向等宽分段，`wave_count` 段（MVP 3 段），段间距 8 px，段高 12 px，各段下方 1 px 基线。三段形态：已过（冷灰描边、空心、不写菜数）、当前（墨黑 2 px 实心底线 + `1/3` 数字）、未揭晓（冷灰底 + `?` + 该波菜数，如 `?4`）。全部直线直角，圆角 ≤ 4 px（`ART-§3`）。
- 数据：`wave_index / wave_count`、每波菜数（`wave_size`，公开信息）、已过波是否被跳/吃空（只区分“已过”，不区分原因）。
- 更新：开局、跳波、吃空自动推进、跨波；**同帧**替换，无飞入、无翻牌、无延迟（`WAVE` Visual“零特效推进”）。
- 紧迫态：无。`?` 槽不脉动、不倒计时、不变色（`WAVE` Game Feel「制造好奇，不是焦虑」）。
- 交互：只读，不可获焦。**不提供“查看整波”入口**（`WAVE-UI`）。
- 玩家可调：随字号重排（见 § 10.2），不单独隐藏。
- 无障碍替代：`?4` 与 `1/3` 都是文字；灰度下靠“实心/空心/问号”三态区分，不靠颜色。

**决议（本规格采用，替代 `HUD-OQ4` 的两种选项）**：波次条**每波一个槽，未揭晓槽内写 `?` + 该波菜数**，不显示每波剩余菜的 pips。理由：① 当前波还剩哪些菜，B 区已经把卡片摊开了，pips 是第二份真相；② 顶栏 72 px 高、30% 宽放不下 8 个字面占位符；③ `WAVE-AC4` 要求“标注数量 4”，`?4` 满足它。**这一条与 `WAVE-AC4` 的字面描述（“第 2、3 波各显示 4 个 `?` 占位”）不同**，已记入 Open Questions 第 4 条待菜单波次 owner 确认。

**4.2.2 回合计数与槽位**

- 视觉描述：一个“数字 + 可选槽位行”的块。数字 `剩余 6 / 10`（标签小一档、冷灰；数字等宽、墨黑、28 px、`min-width` 按 5 位预留）。槽位：`turns_total ≤ 12` 时画 `slots` 个 24×24 px 方格（已用 = 墨黑实心，剩余 = 1 px 描边），总宽 276 px；`> 12` 时不画槽位，只画一根比例条。
- 数据：`turns_remaining` / `turns_total`（`HUD-F:hud_turn_slots`）。不写秒、不写“预计还剩”，不做逐秒递减（`HUD-R12`、`TURN-UI`）。
- 更新：`action_committed` 同帧。槽位与数字**同时**变化，数字先落定，槽位不加过渡。
- 紧迫态：**没有“告急”态**。`turns_remaining = 0` 不做红色、不做闪烁、不弹窗，只把数字画成 `剩余 0 / 10` 并进入只读，等餐局流程切 `Ending`（`HUD-AC3`、`TURN-UI`「耗尽不是弹窗」）。
- 交互：只读，不可获焦。
- 玩家可调：随字号；150% 时若槽位放不下则只保留数字 + 比例条（槽位是装饰，数字是判据）。
- 无障碍替代：整数读数恒在，槽位只是冗余通道。

**4.2.3 净利与回本差额**

- 视觉描述：两行右对齐的读数块。上行净利（带符号，`+39` / `−46`，U+2212），下行差额（无符号，`还差 46 元`）。正净利用回本红（4.6:1，米白底），**负净利用墨黑 + 负号**，不用红也不不用橙（`SETT` Visual“亏损不用红色警示”，橙作文本只有 3.8:1）。回本后差额位置写「已回本」。
- 数据：只读快照里的 `running_net` / `shortfall`（`SETT-R19`）。**HUD 不得把菜品价格相加**去得到它，即使数学上相同（`HUD-R6`、`HUD-AC1`）。
- 更新：`action_committed` 同帧；数字位数变化时容器不重排（`min-width` 按 5 位预留）。
- 紧迫态：三个——`< 0`（墨黑 + 负号 + `还差 N 元`）、`= 0`（回本，显示「已回本」，不显示 0）、`> 0`（回本红 + `+N`，差额位仍写「已回本」）。免单档口（`entry_fee = 0`）从开局第一帧起恒为「已回本」（`HUD-R18`、`SETT-R15`）。
- 交互：只读。
- 玩家可调：随字号；不允许隐藏（信息层级 ②）。
- 无障碍替代：符号 + 中文短句；**灰度后仍可读**是硬性验收（`HUD-AC29`、`ACC-VIS-08`）。

**4.2.4 容量条与读数**

- 视觉描述：横向分段条，`cells` 个方格（`HUD-F:hud_capacity_cells`），已用为橄榄绿实心、剩余为 1 px 空心描边；条右侧（或下方）写 `已用 12 / 20 格`。**条是辅助，数字是判据**：数字永远 28 px 墨黑，橄榄绿永不上文字（4.0:1，见 § 10.1）。
- 数据：`capacity_used` / `capacity_total` / `capacity_remaining`（`STOM-R12`）。容量**逼近上限也不变红**——本作没有“危险容量”，满了只表示放不下下一道（`HUD` Visual）。
- 更新：同帧；`capacity_total = 0` 时显示 `0 / 0`、`fill_ratio = 0`、不除零，并让所有卡写出“总容量为 0”的原因（错误态，不静默当成吃不下）。
- 紧迫态：只有“满”（`used = total`）与“未满”，两者都不产生警示样式；满时按钮与卡片已经足以说明后果。
- 交互：只读，不可获焦。**不做“按可吃性过滤/排序”**（`STOM-UI`、`HUD-R13`）。
- 玩家可调：随字号；宽度跟随顶栏，不与回合块交换位置。
- 无障碍替代：整数读数 + 填充/空缺形状 + 加粗边界（`ART-§4` 色盲安全）。

**4.2.5 菜品卡（可吃 / 不可吃 / 焦点 / 悬停 / 解腻）**

- 视觉描述：一张小票条目。三区固定：左上名称（≤ 2 行，超出省略，完整名进 D 行）、右上价格（28 px 等宽）、中部基础上→实际饱腹（`3 → 5`，追加部分写作 `+2` 并用橄榄绿加深一档描边而非变色文字）、底部口味标签与解腻标记。剪影 ≤ 卡面 40%，纯色块无内绘（`ART-§3`）。卡底米白，1 px 分隔线，圆角 ≤ 4 px。
- 数据：名称、图标、`price`、`satiety`（菜品数值）；`effective_satiety` 与 `+N`、`taste_tags`、`cleanse_target`（腻度与口味）；`can_fit` 与 `capacity_remaining`（胃容量）；是否仍在可见集（菜单波次）。**字段不得折叠进悬浮提示**（`HUD-R8`、`CLOY-UI`、`DISH-UI`）。
- 不可吃态：整卡 40% 不透明度 + 左侧 2 px 提示线，**但原因文字保持 100% 不透明**，写作 `需要 6 格，剩 4 格`（`HUD-R18`、`STOM-UI`）。**它不是禁用控件**：仍可获焦、仍可悬停、仍可读全部字段——它是信息（`HUD-R10`）。这与输入 GDD“禁用控件不可获焦”的区别是：那条说的是**流程禁用**（`Ending` / `frozen`），这条说的是**数据状态**。
- 解腻：含 `酸`/`冰` 的菜在卡角有一个 2 px 的“解”字方标（文字，不是图标）。**选中时**卡片或 D 行写「将解掉：肉 −1」；不选中不写（`CLOY-UI`、`CLOY-R11`）。
- 更新：同帧全部字段一起换；不允许“价格先变、饱腹后到”。焦点卡被吃后，焦点落到**原位置的下一张卡**，不跳回第一张（`HUD-AC37`）。
- 紧迫态：三种卡片态——可吃（常态）、不可吃（40% + 原因）、流程禁用（`Ending`/`Frozen` 时全部卡降到 40% 且不可获焦）。
- 交互：可获焦；`ui_accept` 提交该卡（**只在可吃且未流程禁用时**）。不可吃卡上按 `ui_accept`：卡片横向抖动 ≤ 150 ms + D 行写「放不下」，**不提交动作**（`HUD-R11`、`HUD-AC23`）。
- 玩家可调：随字号（150% 时 2 列）；不允许隐藏字段。
- 无障碍替代：全部数值为文字；不可吃原因句；解腻用“解”字而非颜色。

**4.2.6 焦点详情行 D**

- 视觉描述：一条横贯 B 区的单行（150% 时两行），左侧菜名，右侧依次 `16 元 · 3 格（基础 3 + 腻度 2） · 将解掉 肉 −1 · 需要 6 格，剩 4 格（还差 2 格）`。分隔用 ` · `（U+00B7）而不是竖线，避免与焦点环混淆。
- 数据：焦点卡的只读字段 + `hud_short_cells` 产生的**显示用**差额（`HUD-F:hud_short_cells` 明确只生成文案，不参与判定）。
- 更新：焦点变化同帧；吃菜/跳波后按新焦点重排。
- 紧迫态：三种内容——常态详情、拒绝原因（`放不下` / `没有回合了` / `本局已结束`，150 ms 后恢复常态）、流程禁用时写 `本局已结束` 或 `已暂停`。
- 交互：只读；不抢卡片面积、不挡点击。
- 玩家可调：随字号（两行）。
- 无障碍替代：它是本 HUD 的“文字兜底”，卡上任何被省略的长菜名都从这里读全。

**4.2.7 腻度面板 C1**

- 视觉描述：标题「腻度」+ 若干行 `组名 ×N`（等宽数字）。**只列计数 > 0 的组**，按规范组序（`主食, 蔬菜, 饮料, 甜, 蛋, 辣, 油, 鲜, 肉`）排列，空组不占屏（`CLOY-R12`、`CLOY-UI`）。无计数时整块只写「暂无」（`HUD` 信息清单）。
- 数据：各 `cloying_group` 的本局计数（`CLOY` 拥有；HUD **不得缓存一份独立计数表**）。
- 更新：吃菜同帧。解腻触发后被减 1 的组**当场更新或消失**，不延迟到下一回合（`CLOY` Game Feel「解腻要有可感知的节拍」）。
- 紧迫态：无颜色编码；计数字就是压力本身。
- 交互：只读，不可获焦。
- 玩家可调：随字号；150% 时折成两行，不提供排序或“按腻度过滤”（`CLOY-UI`）。
- 无障碍替代：组名 + `×N` 原文；不靠色块。

**4.2.8 下一波预览 C2**

- 更新：开局锁定；本局中途升级 `MENU_VISION` 不改变本局预览（`WAVE-R11`）。
- 紧迫态：无。
- 交互：只读；**迷你卡即使看起来像卡片也不可获焦**，避免玩家试图点它——不可获焦的卡不加悬停样式。
- 玩家可调：随字号；不可展开。
- 无障碍替代：`预览 2 / 4` 是文字；`?` 数量文字化。

**4.2.9 跳过 / 结束取餐按钮 C3**

- 视觉描述：右栏底部一个整宽按钮（高 = 两行 56 px，150% 三行 76 px），文案即代价：非末波 `跳过本波 · 放弃 3 道 · 花 1 回合`；末波 `结束取餐（免费）`。禁用时 40% 冷灰 + 紧贴下方一行原因：`turns_remaining = 0` 写 `没有回合了`，`turns_remaining = 1` 写 `最后一回合不能跳波`（`HUD-AC26`）。**不用红色警示**——跳过是计划动作，不是危险动作（`WAVE` Visual）。
- 数据：可用性与代价来自菜单波次（`WAVE-R5`、`advance_cost`）。HUD 只把文案与确认面板对着返回值画，**不自行扣回合、不自行丢菜**。
- 更新：开局、进入末波、`turns_remaining` 变为 `≤ 1`（终局帧或最后一回合）；末波「结束取餐」不因回合数禁用。
- 紧迫态：可用 / 禁用（原因必写）。末波时文案整体替换，**按钮位置不动**（`HUD` Game Feel「按钮位置固定」）。
- 交互：可获焦。非末波激活 = **立即提交**，不弹确认（`WAVE-OQ8` 已答）；末波激活 = 打开确认面板。`game_skip_wave`（S / X / 右键）是**全局动作**，非末波直接提交、末波打开面板。
- 玩家可调：无。
- 无障碍替代：代价写在按钮文字里；禁用原因写文字；键盘/手柄可达。

> **右键风险**：`INP-R1` 把 `game_skip_wave` 绑到“右键任意位置”，因此在非末波误触一次 = 丢一整波 + 1 回合。这与 `WAVE-OQ2`（是否给跳过加轻确认）是同一个问题，本规格不裁，记入 Open Questions 第 5 条。

**4.2.10 结束取餐确认面板 E**

- 视觉描述：居中面板，宽 480 px，米白底、圆角 ≤ 4 px、1 px 分隔；标题「结束取餐？」；主体逐条列出**当前波仍会失去的菜**（菜名 + 价格），末尾一行汇总「另有 2 道本局剩余」。底部两个按钮：`取消`（默认焦点）、`确认结束取餐`。面板外 60% 暗底。
- 数据：当前波 `visible_dishes` 的剩余项（菜单波次）+ 价格（菜品数值）+ 本局剩余菜数（菜单波次计数）。**不显示“将损失合计”**——任何求和都违反 `HUD-R6` 的口径所有权，也会把面板变成一份报价。
- 更新：打开时计算一次；打开期间数据不再变化（`run_state` 仍是 `Active`，但没有动作能提交）。
- 紧迫态：**无时限**。等待 60 秒不会自动关闭、不会自动确认（`HUD-R17`、`HUD-AC33`）。
- 交互：**焦点陷阱在面板内**（两个按钮循环），但**不调用** `push_context(Modal)`（那是界面流程的唯一调用点，`HUD-R16`）。`ui_cancel` 关闭并把焦点还给「结束取餐」按钮。**面板打开期间 `game_skip_wave` 一律被吞掉**：不重开、不确认、不提交、视图不变（`HUD-AC27`）。面板外的 HUD 数字**保持可读**，玩家要看着数决定是否收手（`HUD` Visual）。
- 玩家可调：随字号（面板宽度跟着 `s` 缩放；150% 时列表滚动而不是缩小字号）。
- 无障碍替代：全部为文字；默认焦点在「取消」（与 `UIF-R6` 破坏性确认默认取消一致）；键盘/手柄全程可达。

**4.2.11 结束原因 / 错误横幅 F**

- 视觉描述：顶栏下缘一条通栏文本行（1 px 上边线），墨黑正文 + 冷灰补充。`TIME_EXHAUSTED` → 「时间用完了」；`NO_EATABLE_DISH` → 「没有菜可以吃了」。`Faulted` → 「本局数据异常，收益不计」+ 一句原因；错误码只在 debug 构建显示。**不用红色警报、不闪烁**（`ART-§2` 错误语汇：去饱和 + 冷静文案）。
- 数据：`end_reason` / `run_faulted(code, detail)`（`RUN-R8`、`RUN-R18`）。
- 更新：`run_ended` / `run_faulted` 同帧出现，`Settling` 起保持，`Handoff` 淡出（≤ 200 ms）。
- 紧迫态：存在 / 不存在。
- 交互：只读；不提供关闭按钮（收据会覆盖它，`RUN-UI 6`）。
- 玩家可调：不可隐藏（信息层级 ② 的补充）。
- 无障碍替代：纯文字；不依赖红/橙。

**4.2.12 焦点环与悬停（双轨）**

- 键盘/手柄焦点：**2 px 实线外框 + 2 px 间距**，交互蓝（`ART-§3`、`ART-§4`），无发光、无脉动、无缩放。在米白卡底上实测 4.9:1（≥ 3:1 的非文本对比要求）。
- 鼠标悬停：浅色底填充（纸色加深 6%），**不描边**；可与焦点同时出现在不同卡上。
- 同一张卡被同时悬停和聚焦：描边 + 浅底**同时**绘制——玩家要能同时看到“我将要按的”和“我的鼠标在哪”（`HUD` Game Feel、`INP-R8`、`HUD-AC38`）。
- 移动鼠标不改键盘焦点；键盘导航不清除悬停（`HUD-R14`）。
- 不可吃卡照样有焦点环（它不是禁用），但**流程禁用**的卡既无焦点环也无悬停底。
- 焦点在重绘后保持同一张卡；卡消失则落到原位置下一张（`HUD-AC37`）；手柄断开时焦点保持，不重置（`HUD-AC39`）。

**4.2.13 首局引导锚点（HUD 不绘制）**

HUD 向首局引导提供两个只读接口（`ONB-R11`、`ONB-R12`、`HUD-OQ8` 已关闭）：

| 接口 | 返回值 | 约定 |
|---|---|---|
| `get_anchor_rect(anchor_id) -> Rect2` | `top:net` / `top:turns` / `bar:capacity` / `rail:cloy` / `card:<dish_id>` / `grid:first_card` 六类 id 的屏幕矩形 | 当前不存在（卡被吃掉、锚点不可用）时返回**空矩形**；调用方走降级路径。每次请求重新计算，**不缓存** |
| `get_protected_rects() -> Rect2[3]` | 回合读数、容量读数、净利/差额三块矩形 | 任何布局模式（150%、超宽）都必须可判定；取不到时调用方按“不相交”处理并记断言失败 |

HUD 不绘制气泡、遮罩、指引线，不移动焦点，不改变自己的布局。首局引导压 `Blocked` 期间，**三个受保护读数保持原亮度**（`RUN-UI 7`）。

## 5. HUD States by Gameplay Context

本作**没有探索、战斗、对话语境**。模板的四个必查语境按下表映射，新增本作自己的语境。HUD 状态是 `run_state` 的投影加一个独立的 `frozen` 维度，**HUD 不新增玩法状态**（`HUD` States and Transitions）。

| 语境 / 状态 | 触发 | 显示 | 隐藏 / 弱化 | 修改 | 进入转场 |
|---|---|---|---|---|---|
| `Loading`（映射模板“加载”） | Run 场景已挂载、首个快照未到 | 骨架：档口名、空槽位；全部数字 `—` | 卡片区空；右栏空 | 无 | 无动画；不允许任何控件获焦 |
| `Active`（映射模板“探索/常态”） | `run_state = Active` 且 `frozen = false` | 8 个信息块 + D 行 | — | 全部 100% 饱和 | 开局同帧亮起，无淡入（`RUN-UI 1`「首帧就能看见回合、容量与当前波」） |
| `Active` + 确认面板 | 末波激活「结束取餐」 | 全部 + 面板 | 面板外 60% 暗底 | 焦点进入面板陷阱 | 面板淡入 ≤ 180 ms（`reduce_motion` 时 0 ms） |
| `Active` + 首局引导（`Blocked`） | 首局引导压入上下文 | 全部 + 引导气泡 | 遮罩压暗受保护矩形之外 | 三个受保护读数保持原亮度 | 由首局引导控制（淡入 ≤ 100 ms） |
| `Active` + 全不可吃 | 剩余容量放不下任何可见菜 | 全部；所有卡 40% + 原因 | — | 跳过按钮**仍可用** | 无动画；**HUD 不提示“无菜可吃”**，也不结束本局（`HUD` Edge Cases、`RUN-R8`） |
| `Active` + 1 回合 | `turns_remaining = 1` 且非末波 | 全部；回合 `剩余 1 / 10` | — | 跳过按钮禁用 + 「最后一回合不能跳波」；吃菜保持可用 | 无动画 |
| `Active` + 0 回合帧 | `turns_remaining = 0` 但 `run_state` 仍是 `Active` | 全部；回合 `剩余 0 / 10` | — | 跳过按钮禁用 + 「没有回合了」 | 无动画；**不弹“时间到”**（`HUD-AC3`） |
| `Frozen`（映射模板“暂停/菜单”） | `frozen = true` | 全部信息块**仍可见** | 全部控件不可获焦 | 全屏降饱和 40%；暂停菜单在上层 | 降饱和同帧（`reduce_motion` 不影响）；HUD 不监听 `ui_pause`、不自绘暂停菜单（`HUD-R21`、`UIF-R15`） |
| `Ending` | `run_state = Ending` | 全部 + 结束原因横幅 | 全部控件禁用 | 数值冻结，最后一帧保持 | 无动画、不闪白、不清屏（`HUD` Visual「收尾要稳」） |
| `Settling` | `run_state = Settling` | 保持 `Ending` 最后一帧 | — | — | **不清屏**；收据在第一帧覆盖上来（`RUN-UI 6`、`HUD-AC35`） |
| `Handoff` | `run_state = Handoff` | 最后一帧淡出 ≤ 200 ms | — | — | 淡出；`reduce_motion` 时瞬时 |
| `Faulted`（映射模板“错误”） | `run_state = Faulted` / `run_faulted` | 最后一帧 + 错误横幅；受影响数字 `—` | 无控件可获焦 | 顶栏错误码文字 | 无结束动画、不跳转（跳转归场景与流程管理） |
| `Hidden` | `run_state = Idle` / `run_discarded` | 无 | 全部 | — | `run_discarded` 直接回 `Hidden`，不播“本局结束”（`HUD-AC7`） |

**空状态清单**（每个数据依赖元素都必须有，`ux-review` 会逐条查）：

| 元素 | 空状态 | 文案 |
|---|---|---|
| 净利 / 差额 | 查询失败 / `Faulted` | `—`（不显示 0、不显示旧值） |
| 回合 / 容量 / 卡片 | 首帧未到 | `—` / `0 / 0` / 空槽位 |
| 腻度面板 | 无计数 > 0 的组 | 「暂无」 |
| 下一波预览 | `menu_vision = 0` | 「下一波：4 道未揭晓」 |
| 下一波预览 | 最后一波 | 「已是最后一波」 |
| 详情行 | 无焦点 | 整行隐藏（`Active` 首帧必有焦点，故实际只在 `Loading`/`Faulted` 出现） |
| 当前波 | 波内无菜（自动推进中） | 不出现“空波”：自动推进同帧完成（`WAVE-R4`） |
| 确认面板列表 | 末波已无剩余菜 | 「本波已无可放弃的菜」+ 仍可确认 |
| 容量 | `capacity_total = 0`（损坏） | `0 / 0` + 每张卡写「总容量为 0」 |
| 回本差额 | 免单档口 | 「已回本」 |

**`HUD` 七态与本表一一对应**，`Hidden` 是无画面状态：`Loading` / `Active` / `Frozen` / `Ending` / `Settling` / `Handoff` / `Faulted`（`HUD` UI Requirements 第 1 条）。

## 6. Information Hierarchy

层级编号沿用 `HUD`「信息层级」（① 最高）。**前两级在任何分辨率、任何字号下都不得被遮挡**（`HUD` UI Requirements 第 4 条）。

| 元素 | 层级 | 优先级 | 理由 | 被隐藏时由什么承担 |
|---|---|---|---|---|
| 回合（数字） | ① | MUST KEEP | 所有取舍的第一约束；缺了它不能算任何账 | 无替代。槽位可省，数字不可省 |
| 容量（读数与条） | ① | MUST KEEP | 可吃性的判据；缺了它“放不放得下”变成试错 | 无替代 |
| 净利 / 回本差额 | ② | MUST KEEP | 唯一的“赢没赢”读数（支柱 4） | 无替代（收据太晚） |
| 菜品卡（价格 / 饱腹） | ③ | MUST KEEP（`Active` 期间） | 主操作面，没有它无法提交动作 | 无替代 |
| 焦点详情行 | ③ | SHOULD KEEP | 卡片的文字放大与拒绝反馈位 | 卡上已有全部字段；D 行是冗余 + 失败解释 |
| 跳过 / 结束取餐 | ③ | MUST KEEP（`Active` 期间） | 唯一的“不吃”出口；缺了会在放不下时卡死（`WAVE-R5`） | 无替代；`game_skip_wave` 是另一条通道，但不是可见通道 |
| 波次条 | ④ | SHOULD KEEP | 决定“还能等到什么”；可短期靠记忆 | 记忆 + 结算页的“跳过/未吃”列表 |
| 下一波预览 | ④ | CAN HIDE | 只有 `menu_vision > 0` 时存在；玩家为它付过钱，故默认显示 | 无（它是买来的信息） |
| 腻度面板 | ⑤ | SHOULD KEEP（有计数时） | “为什么这道贵了”的解释 | 卡片上的 `+N` 与 D 行「将解掉」已含单道信息 |
| 结束原因横幅 | ② | MUST KEEP（`Ending` 期间） | 失败必须可归因（`RUN-UI 8`） | 无替代 |
| 错误横幅 | ② | MUST KEEP（`Faulted`） | 故障不能静默 | 无替代 |
| 焦点环 / 悬停 | — | MUST KEEP（`Active`，可操作时） | 不可见焦点 = 键盘玩家无法操作 | 无替代 |
| `?` 槽数 | ④ | SHOULD KEEP | 供给量的唯一公开信息 | 无 |
| `run_seed` | — | ALWAYS HIDE（release） | 泄漏刷种子 | — |
| `unit_value` / 推荐 / 最优解 | — | ALWAYS HIDE | 直接给答案，违反支柱 1/2（`DISH-UI`） | — |

**冻结时的隐藏顺序**（`Frozen` / `Ending` 不需要隐藏，只是禁用与降饱和）：本 HUD 在 `Active` 内**不因空间不足而按层级删元素**——所有被删的都必须是“该状态本来就不该有”的元素（末波无预览、无腻度计数、无焦点无 D 行）。若未来某分辨率真的放不下，删除顺序固定为：④ 预览 → ⑤ 腻度细节 → ④ 波次槽（保留索引数字）→ ③ D 行；**① 与 ② 永不删**。

## 8. Feedback & Notification Systems

本 HUD 没有 toast 队列——它只有**一个瞬时文案槽**（D 行的拒绝态）、**一条通栏横幅**和一个**瞬时面板**。规则因此比模板更简单，但每一条都必须写死。

| 通知类型 | 触发系统 | 位置 | 时长 | 进出动画 | 同时上限 | 优先级 | 队列 / 合并 | 可关闭 |
|---|---|---|---|---|---|---|---|---|
| 动作拒绝（放不下 / 没有回合了 / 本局已结束） | 餐局流程 `REJECTED(code)` + HUD 前瞻校验 | D 行 + 卡片抖动 | 文案 150 ms 后恢复；抖动 ≤ 150 ms | 横向抖动 2 px（`reduce_motion` 时改为静态 2 px 左线加深） | 1 | 高 | 同类拒绝在 500 ms 内合并为一次（只刷新计时，不叠加）；新拒绝**替换**当前拒绝文案 | 否 |
| 数字落定（回合 / 容量 / 净利 / 差额） | HUD | 顶栏 | 0 ms（数值同帧到位）+ 可选 ≤ 250 ms 位移回落 | 位移/放大回落叠加在**已经正确**的新值上 | 4 字段 | 高 | 同一字段的连续变化只保留最后一帧，不排队、不插值中间态 | 否 |
| 波次推进（吃空 / 跳波） | 菜单波次 → 餐局流程 | 波次条 + 卡片区 | 0 | **零特效**：占位直接变卡、卡直接消失 | 1 次 | 中 | 不排队；自动推进不产生任何提示 | 否 |
| 结束原因 | 餐局流程 `run_ended` | 通栏横幅 | 持续到收据覆盖 | 同帧出现（无淡入） | 1 | 关键 | **永不排队、永不合并、永不被抑制** | 否 |
| 故障 | 餐局流程 `run_faulted` | 通栏横幅 + 受影响数字 `—` | 持续到离开 | 同帧 | 1 | 关键（最高） | 同上；**preempt 一切** | 否 |
| 解腻生效 | 腻度与口味 | 腻度面板 + 卡片 | 同帧 | 无：行直接更新或消失 | 1 | 中 | 不排队 | 否 |
| 确认面板 | HUD | 居中 | 直到取消/确认 | 淡入 ≤ 180 ms | 1 | 高（阻断面板内交互） | 打开时吞掉 `game_skip_wave`；不吞 `ui_cancel` | **是**（取消 / `ui_cancel`） |
| 首局引导气泡 | 首局引导 | HUD 之上 | 由引导拥有 | ≤ 100 ms 淡入 | 1 | 高 | HUD 不管；只提供锚点并让位 | 由引导拥有 |

**队列规则**

1. **优先级**（高到低）：故障 > 结束原因 > 确认面板 > 动作拒绝 > 数字落定。故障与结束原因**绕过一切队列**，立即绘制。
2. **合并**：同一拒绝原因在 500 ms 内重复触发只刷新文案计时，不叠加、不堆高 D 行；不同原因以最新一条为准（旧的一条不排队）。
3. **不排队的状态事实**：数字、波次、卡片、腻度、容量都**不是通知**——它们是同一帧重绘的现状，永不出现在任何队列里。HUD 不存在“消息积压后补播”的机制。
4. **不乐观更新**：动作被拒绝时 HUD 不预扣回合、不预占容量、不改净利，保持旧值（`HUD` Edge Cases）。

**HUD 发出的语义事件（供音效订阅，HUD 不播音频）**

| 事件 | 时机 | 消费方 |
|---|---|---|
| `dish_action_rejected(reason)` | 拒绝同帧 | `AUD` → `sfx.eat.reject` |
| `number_roll_started(field, from, to, duration_ms)` / `number_roll_finished(field, skipped)` | 数字变化 / 落定 | `AUD` → `sfx.num.tick` / `sfx.num.land` |

> **待裁定**：`AUD` 的 `sfx.num.tick` 按“滚动时间表”播放，但 `HUD-R4` 与 `ART-§1` 原则三要求数字**同帧跳到新值**。本规格的默认实现是**瞬时跳值**，因此 `number_roll_*` 以 `duration_ms = 0`、`skipped = true` 发出（`sfx.num.tick` 自然为 0 次）。是否给净利/容量保留一个“滚动”版本，记入 Open Questions 第 3 条，未静默裁定。

## 9. Platform Adaptation

| 平台 | 安全区 | 分辨率范围 | 输入 | HUD 相关注意 |
|---|---|---|---|---|
| PC Windows / Linux / macOS（窗口） | 5% 短边（36 px @720p） | 1280×720 – 3840×2160 | 键鼠 + 手柄（部分） | 窗口拉伸时按 `hud_ui_scale` 整层缩放，不重排断行；不做 DPI 二次缩放 |
| PC 全屏 / 电视连接 | 5% 短边（54 px @1080p，96 px 上限） | 同上 | 键鼠 + 手柄 | 电视观看距离下最小字号按 720p 基准 ×1.5 生效（30 px 正文）；不依赖鼠标悬停可玩 |
| 2560×1080 / 3440×1440（21:9 及以上） | 5% 短边 | 同上 | 键鼠 + 手柄 | 字号不放大、`s` 停在 1.5；多出的宽度给主区；主区宽度上限 `1600×s`；卡片不拉成细长条（列数上限 4） |
| 1280×800（Steam Deck，16:10） | 未定（`HUD-OQ7`） | 固定 | 手柄 + 触屏 | **本规格不给承诺**：`s = min(1.0, 1.111) = 1.0`，安全边距按高度为 40 px，纵向多出 80 px；是否单开一档待 `ui-programmer` 定。触屏不提供虚拟摇杆（`INP-OQ5`） |

**跨平台一致性要求**

- **不提供 HUD 元素重排**（不提供布局编辑器）。理由：仅 PC、无主机认证要求，且 `HUD` 布局是固定九宫格，重排会破坏“回合/容量/净利三块永不遮挡”的判据。代价记入 `design/accessibility-requirements.md` 的 Known Intentional Limitations。
- **不画键位图标**：按钮与提示只写语义（「跳过本波」），不写 `S` / `X` / 右键。理由：`INP-OQ2`（手柄图标是否按设备替换）未决，HUD 若画死键位就会在切设备后说谎。键位说明归首局引导与设置。
- **窗口失焦 / 最小化**：不消耗回合；恢复时直接画当前快照，不追帧、不补播动画。
- **手柄断开**：焦点停在原卡，不重置；HUD 不显示设备错误（由场景与流程管理处理）。

## 10. Accessibility

HUD 专项要求；项目级标准见 `design/accessibility-requirements.md`（Tier **Standard**）。以下数字均已用 `HUD-F:hud_contrast_ratio`（sRGB，WCAG 公式）核算，**不是估计**。

### 10.1 Colorblind Modes（色相不是唯一通道）

本作不靠“切一套色盲调色板”来救——**结构编码优先**（`ART-§4` 色盲安全）。因此下表每一行都必须成立，无论玩家用哪套调色板、或截图被转成灰度。

| 元素 | 颜色承担了什么 | 颜色之外的通道 | 状态 |
|---|---|---|---|
| 净利 / 差额 | 正收益红、负值墨黑 | `+` / `−`（U+2212）符号 + 「还差 46 元」/「已回本」文字 + 位置（金额区） | 已定 |
| 容量条 | 橄榄绿 = 已用 | 填充/空缺形状 + 加粗边界 + `已用 12 / 20 格` 整数 | 已定 |
| 卡片可吃性 | 40% 不透明度 + 2 px 左线 | 「需要 6 格，剩 4 格」原因句（100% 不透明） | 已定 |
| 解腻 | 橄榄绿描边 | 「解」字方标 + D 行「将解掉：肉 −1」 | 已定 |
| 波次条 | 冷灰 = 未揭晓 | `?` 字符 + 菜数（`?4`）+ 实心/空心 | 已定 |
| 焦点 vs 悬停 | 蓝描边 vs 浅底 | 形状不同（描边环 / 无环填充）、可同屏并存 | 已定 |
| 结束 / 错误横幅 | 无颜色编码 | 纯文字句 | 已定 |
| 不可吃 vs 流程禁用 | 都是“灰” | 不可吃有原因句且可获焦；流程禁用无原因句、有焦点也不出环 | 已定 |

**文本色使用规则（实测驱动）**：

| 组合 | 实测对比度 | 允许用途 |
|---|---|---|
| 墨黑 `#1F1F1C` / 米白 `#F5F1E6` | **≈ 14.6:1** | 全部正文与数字 |
| 回本红 `#C63A2F` / 米白 | **≈ 4.6:1** | 仅正收益数字与 2 px 线；**只允许米白底** |
| 交互蓝 `#2F6F8F` / 米白 | **≈ 4.9:1** | 仅焦点环、悬停/选中；≤ 2 px，不填充 |
| 橄榄绿 `#6E7C3C` / 米白 | **≈ 4.0:1** | **不得用于文字**；只用于容量条填充 |
| 警示橙 `#B5651D` / 米白 | **≈ 3.8:1** | **不得用于文字**；仅 2 px 线；MVP 不使用 |
| 回本红 / 深面板 `#1F2A24` | **≈ 2.9:1** | **禁止**：这就是“数字必须落在米白底”的原因 |

> `HUD-R19` 写“红色只用于负值强调”，与 `ART-§4`（红 = 收益与关键读数）以及 `SETT` Visual（亏损不用红色警示）冲突。本规格按艺术圣经 + 结算 GDD 执行：**负值 = 墨黑 + 负号**，红只给正收益与关键读数。冲突见 Open Questions 第 2 条。

### 10.2 Text Scaling

三档 **100% / 125% / 150%**（`UIF-R24` 的 `text_scale_percent`，与 `HUD-F:hud_card_columns` 的 `τ` 同一开关）。缩放**只放大文字与行高**，不放大图标与安全边距；容器按规则重排。

| 元素 | 100% | 125% | 150% | 溢出行为 |
|---|---|---|---|---|
| 波次条 | 3 段 + `1/3` | 通过 | 通过 | 槽宽按文字收紧；放不下时只保留 `波次 1/3 · 2 波未揭晓（各 4 道）` 一行文字，不折第三行 |
| 回合读数 | 数字 28 px + 10 槽 | 通过 | 通过 | 150% 时不画槽位，只保留数字 + 比例条（槽位是冗余通道） |
| 净利 / 差额 | 两行 | 通过 | 通过 | 不折成三行；差额句上限 8 字（`还差 46 元`） |
| 容量条 | 20 格 + 读数 | 通过 | 通过 | 格宽下限 6 px；150% 时允许减到 16 格视觉分段，读数仍是精确值 |
| 菜品卡 | 4 列，216×176 | 3 列 | 2 列，448×224 | 名称 2 行截断（完整名进 D 行）；价格与饱腹同行，不折行；卡高随行高增加 |
| 详情行 D | 1 行，44 px | 1 行，56 px | 2 行，72 px | 超出 2 行即视为文案缺陷，回改文案表 |
| 腻度面板 | 每行 `组名 ×N` | 通过 | 两行折行 | 组名不与计数分列；不截断计数 |
| 下一波预览 | 3 迷你卡 + `?` | 2 迷你卡 | 2 迷你卡 | 少一张卡不算丢信息（`预览 2 / 4` 文字仍在） |
| 跳过按钮 | 2 行 56 px | 2 行 | 3 行 76 px | 文案上限 22 字符 / 3 行 |
| 确认面板 | 列表 + 两按钮 | 通过 | 通过 | 列表区滚动，不缩字号；按钮文字不折 |

**150% 的架构性后果**：卡片降到 2 列（`HUD-AC11`），网格 2×2 占 464 px 高，与 D 行之间只剩 16 px 余量（见 § 3.2）；这是全 HUD 最紧的一处，必须实机复核。**任何元素在 150% 下都不许消失**（信息层级 ③④⑤ 允许换行，不允许删）。

### 10.3 Motion Sensitivity

| 动效 | 强度 | 减少动态（`reduce_motion`）时 | 替代 |
|---|---|---|---|
| 数字变化位移 / 放大回落（≤ 250 ms） | 轻 | 关闭 | 瞬时替换 |
| 卡片焦点描边加粗（≤ 120 ms） | 轻 | 关闭过渡 | 描边瞬间变粗（样式差异保留） |

| `Handoff` 淡出（≤ 200 ms） | 轻 | 关闭 | 瞬时消失 |
| 暂停降饱和（40%） | 无（静态） | 保留 | — |
| 波次推进 / 数字滚动 | 无（本就不做） | — | — |
| 任何粒子、闪光、屏幕震动 | — | **本 HUD 不产生** | — |

### 10.4 Subtitles Specification

**N/A**。本作 MVP 无配音、无对话、无旁白（`game-concept` 无叙事系统；`AUD` 的 cue 全部是语义音效）。因此不设字幕区、不设说话人标识。语义音效的可替代通道见 `design/accessibility-requirements.md` 的 Auditory Accessibility。**若未来加入配音，本节必须重写，且字幕区不得占用 B 区卡片面积。**

### 10.5 HUD Opacity and Visibility Controls

设置归界面流程（`UIF-R24`），HUD 只消费。

| 设置 | 范围 | 默认 | 效果 |
|---|---|---|---|
| `hud_opacity_percent` | **60–100** | 100 | 对每个 HUD 元素乘合成 alpha；**文字 α 恒为 1.0**，面板底色单独钳制 ≥ 0.70 —— 因此 60% 时数字仍是纯色落在 ≥ 0.70 的面板上，对比度仍 ≥ 4.5:1（`HUD-AC32`）。**不提供 0%（全关 HUD）**：0% 会让本局无法进行（回合、容量、净利全不可见），记入 Open Questions 第 6 条 |
| `text_scale_percent` | 100 / 125 / 150 | 100 | 见 § 10.2 |
| `reduce_motion` | 开 / 关 | 关 | 见 § 10.3 |
| 分元素显隐 | **不提供** | — | 只给全局不透明度；隐藏回合/容量会直接毁掉可玩性 |
| HUD 元素重排 | **不提供** | — | 见 § 9 |

### 10.6 Keyboard / Gamepad

- **完整可玩**：只用键盘、或只用手柄都能从开局走到结算（`INP-R4`、`INP-AC4`）。HUD 内所有可获焦元素：4 张卡 + 1 个操作按钮 = **5 个焦点位**（150% 时仍是 5 个）。
- **焦点链**：卡片网格按**屏幕位置**（上/下/左/右按卡片矩形中心，不按节点树）→ C3 按钮 → 回到第一张卡。只读块（顶栏、腻度、预览、D 行）**不进入焦点链**。
- **初始焦点**：`Active` 首帧落在当前波第一张**可吃**菜；全不可吃则第一张卡（`HUD-AC36`）。
- **焦点陷阱**：确认面板内循环（取消 ⇄ 确认），`ui_cancel` 关闭并还原到「结束取餐」。
- **不可达即缺陷**：如果一个动作只能靠鼠标完成（例如只能点击卡片、只能右键跳过），即为缺陷。`game_skip_wave` 有键盘与手柄绑定（S / X），因此右键不是唯一通道。
- **悬停不是前置条件**：任何信息都不只存在于悬停态。

### 10.7 Grayscale

一份去掉色相的截图必须能读出：**净利正负、是否回本、可吃性、跳过代价、容量余量、波次进度、腻度计数、焦点位置、结束原因**（`HUD-AC29`、`ACC-VIS-08`）。做法是把 § 10.1 的表逐行当作验收用例，不靠肉眼。

## 12. Acceptance Criteria

QA 无需读其它文档即可逐条验证。全部基于 1280×720 参考分辨率，另注明处除外。

**布局与安全区**

- [ ] 1. 1280×720 下所有 HUD 元素的外缘距视口边 ≥ 36 px；1920×1080 下 ≥ 54 px；3840×2160 下 = 96 px（不随 4K 继续增大）
- [ ] 2. 任一受支持分辨率与任一文档化状态下，两个 HUD 信息块都不重叠（含 150% 字号与 21:9）
- [ ] 3. 顶栏 + 右栏的可见面积占全屏 ≤ 28%（1280×720 实测应为 26.5%）
- [ ] 4. 屏幕中央 40% 区域内，`Active` 状态只有可交互的菜品卡；确认面板打开时额外只有该面板
- [ ] 5. 150% 字号下：卡片为 2 列 × 2 行、顶栏 ≤ 96 px、详情行 2 行，且网格与详情行之间余量 ≥ 0（不重叠）
- [ ] 6. 2560×1080 下卡片仍为 4 列、字号与 1080p 相同（不因超宽放大）
- [ ] 7. 窗口从 1280×720 拉大到 1920×1080 再拉回，安全边距与所有矩形按公式变化，无文字断行错位、无元素出界

**信息与数字**

- [ ] 8. 开局第一帧（尚未吃任何菜）净利显示 `−85`、差额显示「还差 85 元」，不等第一道菜
- [ ] 9. 吃过 16 / 5 / 18 元三道菜后，净利显示 `−46`、差额「还差 46 元」，且与同一帧快照的 `running_net` / `shortfall` 完全一致
